# 에이전트 사용 지침

이 지식베이스는 UI/UX 개념 설명, 비교, 리뷰, 명세, 리서치·검증 계획을 위해 설계되었다. 에이전트는 전체 문서를 한 번에 넣지 말고 검색 결과에서 가장 관련성이 높은 2~5개 가이드를 읽어야 한다.

## 근거 수준

1. **규범 표준:** 접근성 성공 기준처럼 출처가 규범적 요구를 정의하는 내용.
2. **출처 기반 종합:** 여러 공개 가이드의 공통 방향을 이 프로젝트가 재구성한 내용.
3. **실무 권고:** 문맥에 따라 달라질 수 있으나 반복적으로 유용한 운영·검증 방법.
4. **맥락적 추론:** 사용자가 제공한 제품·화면·데이터에 근거해 에이전트가 도출한 판단.

에이전트는 이 네 수준을 혼합해 사실처럼 표현하지 않는다. 실제 구현을 보지 못한 상태에서는 접근성 준수, 키보드 동작, 성능, 보조기술 호환성을 확정하지 않는다.

## 검색

```bash
python3 scripts/search_kb.py --query "폼 오류 입력값 보존 포커스" --top 6
```

JSON 출력:

```bash
python3 scripts/search_kb.py --query "모달 포커스 닫기 복귀" --top 6 --json
```

특정 가이드:

```bash
python3 scripts/search_kb.py --id 026 --full
```

## 작업 모드

### 설명

정의, 적용 맥락, 원리, 예외, 짧은 사례, 검증 질문 순으로 답한다.

### 비교

비교 기준을 먼저 정하고 각 접근의 적합 조건, 비용, 위험, 선택 규칙을 표로 제시한다.

### 리뷰

각 이슈를 `심각도 → 관찰 증거 → 적용 기준 → 사용자 영향 → 수정안 → 검증 방법` 순으로 작성한다. 이미지에 보이지 않는 동작은 **미검증**으로 표시한다.

### 명세

사용자·과업, 상태와 전이, 콘텐츠, 데이터·권한, 오류·복구, 반응형, 키보드·포커스, 보조기술, 터치, 모션, 개인정보, 성능, 분석, 인수 기준을 포함한다.

### 계획

질문, 가정, 방법, 모집, 과업·자극물, 윤리·개인정보, 분석, 성공·반증 기준, 일정이 아니라 의사결정 게이트를 작성한다.

## 규범 언어

- **MUST:** 위반 시 핵심 품질이 훼손되는 요구사항. 예외가 있으면 위험 수용과 승인 근거가 필요하다.
- **SHOULD:** 강한 권고. 따르지 않을 경우 맥락, 대안, 사용자 영향, 검증을 기록한다.
- **MAY:** 선택 사항. 구현 편의가 아니라 사용자 결과와 위험으로 대안을 비교한다.

## 최신성

`time_sensitive: true`인 문서는 성능 지표, 도구, 제품 패턴, 운영 권고처럼 바뀔 수 있는 내용을 포함한다. 적용 시점의 공식 자료를 확인할 수 없으면 숫자·기능·지원 상태를 **미검증**으로 표시한다.

## 답변의 근거 표기

답변 마지막에 사용한 가이드와 핵심 출처를 다음 형식으로 적는다.

```text
근거 가이드
- [uiux-playbook-018] 폼과 검증 — w3c-wcag22, wai-forms, govuk-validation
- [uiux-playbook-020] 오류·복구·실행 취소 — govuk-error-message, nng-heuristics
```

## 금지 사항

- 제공되지 않은 사용자 연구 결과, 수치, 정책, 기술 제약을 만들어내지 않는다.
- 특정 제품 디자인 시스템의 선택을 보편 표준으로 단정하지 않는다.
- 자동 검사 통과를 완전한 접근성 준수로 표현하지 않는다.
- 정적 화면을 보고 동적 상태와 포커스 관리가 정상이라고 단정하지 않는다.
- 현재 법률·규제 준수 여부를 이 지식베이스만으로 판정하지 않는다.
