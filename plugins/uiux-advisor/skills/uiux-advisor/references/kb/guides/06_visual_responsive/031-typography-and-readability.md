# 타이포그래피와 읽기 품질

## 한 문장 원칙

서체의 개성보다 텍스트의 역할, 언어, 크기, 줄 길이, 행간, 대비, 확대와 플랫폼 렌더링을 우선해 읽기 품질을 설계한다.

## 적용 상황

작은 본문, 긴 줄, 과도한 굵기·대문자, 낮은 대비, 고정 행 높이로 번역·확대 시 잘림이 발생하거나 타이포 스케일이 역할과 연결되지 않을 때 사용한다.

## 이 가이드가 답하는 결정

1. 이 문제에서 반드시 지켜야 할 사용자 결과와 품질 경계는 무엇인가?
2. 어떤 상태·맥락·사용자 조건을 포함해야 설계가 실제 환경에서 무너지지 않는가?
3. 어떤 증거와 검증 방법으로 이 결정을 승인·수정·폐기할 것인가?

## 핵심 원리

### 역할 기반 타입 램프

크기 이름이 아니라 페이지 제목, 섹션 제목, 본문, 보조, 레이블, 데이터 등 의미 역할에 타입 토큰을 연결한다.

### 가독성과 판독성

글자 형태를 구분할 수 있는 판독성과 문장·문단을 이해하기 쉬운 가독성을 모두 고려한다.

### 언어별 요구

한글·라틴·숫자·기호·혼합 언어는 자폭, 행간, 굵기, 줄바꿈과 폰트 대체가 다르다.

### 사용자 확대 존중

브라우저·운영체제 글자 크기와 확대를 막지 않고 텍스트가 잘리거나 겹치지 않게 한다.

### 위계 절제

크기·굵기·색·간격을 동시에 과도하게 바꾸지 않고 제한된 단계로 구조를 전달한다.

## 규범적 요구사항

> **MUST**는 위반 시 사용자 과업·안전·접근성·신뢰 또는 검증 가능성이 실질적으로 훼손되는 요구사항이다.  
> **SHOULD**는 특별한 맥락과 근거가 있을 때만 예외를 허용하는 강한 권고다.  
> **MAY**는 선택 가능한 구현 방식이며, 대안의 사용자 결과와 위험을 기록해야 한다.

### MUST

- **MUST:** 타입 토큰을 의미 역할, 최소·최대 크기, 행간, 굵기, 사용 맥락과 연결한다.
- **MUST:** 본문과 인터랙션 텍스트가 사용자 확대와 재배치에서 잘리거나 겹치지 않게 한다.
- **MUST:** 제목 스타일과 실제 제목 요소의 의미 수준을 혼동하지 않는다.
- **MUST:** 텍스트 대비와 링크·상태 구분을 색상 외 단서와 함께 충족한다.
- **MUST:** 지원 언어의 문자·숫자·기호·강조·긴 단어·줄바꿈·폰트 대체를 테스트한다.

### SHOULD

- **SHOULD:** 긴 본문은 적절한 줄 길이, 문단 간격, 소제목, 목록으로 스캔과 지속 읽기를 돕는다.
- **SHOULD:** 전부 대문자, 이탤릭, 매우 가는 굵기, 과도한 자간을 긴 텍스트와 핵심 지침에 사용하지 않는다.
- **SHOULD:** 숫자 데이터는 자리 정렬, 단위, 소수점, 부호와 폰트 숫자 기능을 일관되게 한다.
- **SHOULD:** 웹폰트 실패·지연 시 대체 폰트로 레이아웃과 의미가 유지되게 한다.

### MAY

- **MAY:** 프로젝트의 플랫폼·도메인·조직 제약이 정당화하면 다른 패턴을 선택할 수 있다. 단, 사용자 결과, 접근성, 위해, 되돌리기 가능성, 검증 계획을 결정 로그에 남긴다.
- **MAY:** 검증 비용을 줄이기 위해 충실도와 방법을 조정할 수 있다. 단, 조정으로 답할 수 없게 된 질문과 미검증 영역을 명시한다.

## 설계·실행 절차

1. 콘텐츠 역할, 언어, 기기, 읽기 길이, 밀도 요구를 목록화한다.
2. 제한된 타입 역할과 크기·행간·굵기 토큰을 정의한다.
3. 제목 구조, 본문 폭, 목록·표·폼·숫자·링크의 세부 규칙을 정한다.
4. 실제 언어와 긴·짧은 콘텐츠, 폰트 실패, 확대에서 스트레스 테스트한다.
5. 가독성, 오독, 스캔, 과업 성공을 사용자와 보조기술로 검증한다.
6. 새 역할 추가와 예외 사용을 디자인 시스템 거버넌스에서 관리한다.

## 예외·극단 상황

- 한글과 영문·숫자가 자주 혼합되는 금융·개발 도구
- 코드·수식·표·긴 식별자처럼 줄바꿈 규칙이 다른 콘텐츠
- 사용자가 글자 크기·밀도·서체를 개인화하는 제품
- 브랜드 폰트가 일부 문자나 굵기를 지원하지 않는 경우
- 인쇄·PDF·웹 화면을 같은 콘텐츠에서 지원하는 경우

## 실패 패턴과 교정

| 실패 패턴 | 교정 방법 |
|---|---|
| 브랜드 폰트를 모든 본문에 강제한다. | 지원 문자, 화면 가독성, 성능을 평가하고 본문용 대안을 허용한다. |
| 시각 크기만 바꾸고 제목 요소는 모두 같은 수준이다. | 의미 구조와 시각 역할을 함께 설계한다. |
| 고정 높이 버튼·입력에 긴 텍스트가 잘린다. | 콘텐츠 확장과 줄바꿈을 허용하고 최소 높이로 설계한다. |
| 연한 회색 작은 글씨로 보조 정보를 표현한다. | 정말 보조인지 검토하고 읽을 수 있는 크기·대비·위치를 제공한다. |
| 폰트 로딩 중 레이아웃이 크게 이동한다. | 대체 폰트 메트릭과 로딩 전략을 조정하고 현장 성능을 측정한다. |

## 검증 방법

1. 지원 언어별 실제 콘텐츠로 제목·본문·폼·표·숫자·오류를 검토한다.
2. 브라우저 글자 크기와 200%·400% 확대에서 잘림·겹침·가로 스크롤을 확인한다.
3. 저시력·난독·인지적 부담 맥락에서 찾기·읽기·이해 과업을 테스트한다.
4. 웹폰트 차단·느린 로딩·대체 폰트에서 레이아웃 안정성과 가독성을 측정한다.

## 인수 기준

- [ ] 타입 토큰을 의미 역할, 최소·최대 크기, 행간, 굵기, 사용 맥락과 연결한다.
- [ ] 본문과 인터랙션 텍스트가 사용자 확대와 재배치에서 잘리거나 겹치지 않게 한다.
- [ ] 제목 스타일과 실제 제목 요소의 의미 수준을 혼동하지 않는다.
- [ ] 텍스트 대비와 링크·상태 구분을 색상 외 단서와 함께 충족한다.
- [ ] 지원 언어의 문자·숫자·기호·강조·긴 단어·줄바꿈·폰트 대체를 테스트한다.
- [ ] 지원 언어별 실제 콘텐츠로 제목·본문·폼·표·숫자·오류를 검토한다.
- [ ] 브라우저 글자 크기와 200%·400% 확대에서 잘림·겹침·가로 스크롤을 확인한다.
- [ ] 저시력·난독·인지적 부담 맥락에서 찾기·읽기·이해 과업을 테스트한다.

## 에이전트 적용 규칙

- 폰트 추천보다 역할·크기·행간·언어·확대·성능 기준을 우선 제시한다.
- 특정 수치를 모든 제품의 절대 기준으로 단정하지 말고 WCAG 요구와 실제 검증을 구분한다.
- 시각 스타일과 의미적 제목 구조를 별도 확인한다.
- 입력에 근거가 없으면 사실을 보충하지 말고 가정, 확인 질문 또는 검증 과제로 표시한다.
- 정적 이미지·텍스트만 제공된 경우 키보드, 포커스, 보조기술, 성능, 동적 상태를 통과했다고 단정하지 않는다.
- 권고를 제시할 때 사용자 영향, 트레이드오프, 검증 방법을 함께 적는다.

## 범위와 근거 수준

이 문서는 공개 표준, 공공 서비스 가이드, 제품 디자인 시스템, UX 연구 자료를 교차해 재구성한 독립적인 한국어 실무 가이드다. 특정 출처의 원문을 대체하거나 특정 조직의 승인·제휴를 의미하지 않는다.

규범 표준에 직접 근거한 요구사항과 여러 출처를 종합한 실무 권고를 구분해 사용한다. 법률·규제 준수, 현재 제품 기능, 최신 브라우저·보조기술 지원, 성능 지표와 임계값처럼 변할 수 있는 사항은 적용 시점의 공식 자료와 실제 구현으로 다시 확인한다.
