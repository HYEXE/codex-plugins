# 시각적 위계와 레이아웃

## 한 문장 원칙

크기·위치·간격·정렬·대비를 사용자의 읽기 순서와 행동 우선순위에 맞춰 일관되게 사용하고 의미 구조와 어긋나지 않게 한다.

## 적용 상황

화면의 모든 요소가 강조되어 핵심을 찾기 어렵거나, 카드·구분선·색상이 과도하고, 시각 순서와 키보드·스크린 리더 순서가 다를 때 사용한다.

## 이 가이드가 답하는 결정

1. 이 문제에서 반드시 지켜야 할 사용자 결과와 품질 경계는 무엇인가?
2. 어떤 상태·맥락·사용자 조건을 포함해야 설계가 실제 환경에서 무너지지 않는가?
3. 어떤 증거와 검증 방법으로 이 결정을 승인·수정·폐기할 것인가?

## 핵심 원리

### 과업 중심 위계

브랜드나 조직 중요도가 아니라 사용자가 현재 판단하고 행동하는 순서에 따라 강조한다.

### 근접과 그룹

관련 요소는 간격과 정렬로 묶고 서로 다른 영역은 충분히 분리해 구분선·박스의 남용을 줄인다.

### 일관된 리듬

공간, 그리드, 정렬, 타이포 위계가 반복되면 사용자가 구조를 학습하고 예측할 수 있다.

### 시각·의미 순서 일치

CSS 재배치나 복잡한 그리드로 보이는 순서와 DOM·포커스 순서를 다르게 만들지 않는다.

### 밀도와 여백의 목적

여백은 장식이 아니라 그룹·우선순위·터치·읽기 속도를 조절한다. 데이터 밀도는 과업과 숙련도에 맞춘다.

## 규범적 요구사항

> **MUST**는 위반 시 사용자 과업·안전·접근성·신뢰 또는 검증 가능성이 실질적으로 훼손되는 요구사항이다.  
> **SHOULD**는 특별한 맥락과 근거가 있을 때만 예외를 허용하는 강한 권고다.  
> **MAY**는 선택 가능한 구현 방식이며, 대안의 사용자 결과와 위험을 기록해야 한다.

### MUST

- **MUST:** 페이지의 1차 목표, 핵심 정보, 주요 행동, 보조 정보를 우선순위로 정의한다.
- **MUST:** 시각적 제목·그룹·순서가 의미 구조와 키보드 탐색 순서에 일치하게 한다.
- **MUST:** 색상·크기만으로 의미를 전달하지 않고 레이블·구조·위치와 함께 사용한다.
- **MUST:** 확대, 긴 콘텐츠, 번역, 동적 오류에서 겹침·잘림·가려짐 없이 재배치되게 한다.
- **MUST:** 고정·부유 요소가 콘텐츠, 포커스, 오류 메시지, 브라우저 UI를 가리지 않게 한다.

### SHOULD

- **SHOULD:** 박스와 구분선을 추가하기 전에 간격·정렬·제목으로 그룹을 표현할 수 있는지 검토한다.
- **SHOULD:** 반복 화면에서 동일한 정보와 행동은 동일한 위치·위계로 제공한다.
- **SHOULD:** 전문가용 고밀도와 초보용 설명을 사용자 설정 또는 점진적 공개로 조절한다.
- **SHOULD:** 실제 콘텐츠 길이와 빈·로딩·오류 상태를 사용해 레이아웃을 검증한다.

### MAY

- **MAY:** 프로젝트의 플랫폼·도메인·조직 제약이 정당화하면 다른 패턴을 선택할 수 있다. 단, 사용자 결과, 접근성, 위해, 되돌리기 가능성, 검증 계획을 결정 로그에 남긴다.
- **MAY:** 검증 비용을 줄이기 위해 충실도와 방법을 조정할 수 있다. 단, 조정으로 답할 수 없게 된 질문과 미검증 영역을 명시한다.

## 설계·실행 절차

1. 사용자 과업과 읽기·결정·행동 순서를 작성한다.
2. 콘텐츠를 의미 그룹과 우선순위로 구조화한 뒤 레이아웃 후보를 만든다.
3. 그리드, 간격, 정렬, 타이포, 대비 규칙을 토큰과 패턴으로 정한다.
4. 시각 순서와 DOM·포커스·읽기 순서를 비교한다.
5. 작은 화면·확대·긴 번역·오류·빈 상태로 스트레스 테스트한다.
6. 과업 탐색 시간, 오클릭, 반복 스크롤, 놓친 정보로 위계를 개선한다.

## 예외·극단 상황

- 실시간 경고와 주요 과업이 동시에 경쟁하는 운영 대시보드
- 광고·추천·프로모션이 핵심 콘텐츠와 섞이는 상업 화면
- 사용자가 열·패널·밀도를 개인화하는 업무 도구
- 세로 쓰기·오른쪽에서 왼쪽 방향·긴 번역을 지원하는 경우
- 고정 헤더·하단 행동·쿠키 배너가 작은 화면에서 겹치는 경우

## 실패 패턴과 교정

| 실패 패턴 | 교정 방법 |
|---|---|
| 모든 카드에 그림자와 테두리를 사용한다. | 의미 그룹을 간격·정렬·배경 변화로 최소한 표현한다. |
| 시각적으로 오른쪽 요소를 먼저 보이게 하지만 DOM은 나중이다. | 시각 순서와 의미·포커스 순서를 함께 재구성한다. |
| 주요 행동이 여러 개 같은 강조를 받는다. | 현재 과업의 기본 경로와 대안을 명확히 우선순위화한다. |
| 고정 헤더가 포커스와 앵커 대상을 가린다. | 스크롤 여백과 포커스 가시성을 보장하고 고정 높이를 줄인다. |
| 더미 짧은 텍스트만으로 레이아웃을 승인한다. | 실제 최장·최단·다국어·오류 콘텐츠로 검증한다. |

## 검증 방법

1. 5초 노출 후 사용자가 페이지 목적, 핵심 정보, 주요 행동을 식별하는지 확인한다.
2. 키보드·스크린 리더 순서가 보이는 순서와 자연스럽게 일치하는지 검증한다.
3. 200%·400% 확대와 작은 뷰포트에서 콘텐츠 재배치와 가림을 테스트한다.
4. 실제 과업에서 시선 추적보다 찾기·이해·행동 성공을 우선 측정한다.

## 인수 기준

- [ ] 페이지의 1차 목표, 핵심 정보, 주요 행동, 보조 정보를 우선순위로 정의한다.
- [ ] 시각적 제목·그룹·순서가 의미 구조와 키보드 탐색 순서에 일치하게 한다.
- [ ] 색상·크기만으로 의미를 전달하지 않고 레이블·구조·위치와 함께 사용한다.
- [ ] 확대, 긴 콘텐츠, 번역, 동적 오류에서 겹침·잘림·가려짐 없이 재배치되게 한다.
- [ ] 고정·부유 요소가 콘텐츠, 포커스, 오류 메시지, 브라우저 UI를 가리지 않게 한다.
- [ ] 5초 노출 후 사용자가 페이지 목적, 핵심 정보, 주요 행동을 식별하는지 확인한다.
- [ ] 키보드·스크린 리더 순서가 보이는 순서와 자연스럽게 일치하는지 검증한다.
- [ ] 200%·400% 확대와 작은 뷰포트에서 콘텐츠 재배치와 가림을 테스트한다.

## 에이전트 적용 규칙

- 레이아웃 평가에서는 취향보다 과업 우선순위, 의미 구조, 확대·콘텐츠 변이를 근거로 삼는다.
- 보이지 않는 DOM·포커스 순서는 이미지 만으로 단정하지 말고 검증 필요로 표시한다.
- 카드·구분선 추가를 기본 해결책으로 제안하지 않는다.
- 입력에 근거가 없으면 사실을 보충하지 말고 가정, 확인 질문 또는 검증 과제로 표시한다.
- 정적 이미지·텍스트만 제공된 경우 키보드, 포커스, 보조기술, 성능, 동적 상태를 통과했다고 단정하지 않는다.
- 권고를 제시할 때 사용자 영향, 트레이드오프, 검증 방법을 함께 적는다.

## 범위와 근거 수준

이 문서는 공개 표준, 공공 서비스 가이드, 제품 디자인 시스템, UX 연구 자료를 교차해 재구성한 독립적인 한국어 실무 가이드다. 특정 출처의 원문을 대체하거나 특정 조직의 승인·제휴를 의미하지 않는다.

규범 표준에 직접 근거한 요구사항과 여러 출처를 종합한 실무 권고를 구분해 사용한다. 법률·규제 준수, 현재 제품 기능, 최신 브라우저·보조기술 지원, 성능 지표와 임계값처럼 변할 수 있는 사항은 적용 시점의 공식 자료와 실제 구현으로 다시 확인한다.
