# 모션·애니메이션·감소된 모션

## 한 문장 원칙

모션은 상태 변화, 공간 관계, 원인과 결과를 설명할 때만 사용하고 사용자 설정, 주의, 멀미, 성능과 과업 속도를 존중한다.

## 적용 상황

장식 애니메이션이 과업을 지연하거나 자동 재생·시차 효과가 불편을 주고, 감소된 모션 설정에서도 같은 효과가 재생되며, 상태 전환이 움직임 없이는 이해되지 않을 때 사용한다.

## 이 가이드가 답하는 결정

1. 이 문제에서 반드시 지켜야 할 사용자 결과와 품질 경계는 무엇인가?
2. 어떤 상태·맥락·사용자 조건을 포함해야 설계가 실제 환경에서 무너지지 않는가?
3. 어떤 증거와 검증 방법으로 이 결정을 승인·수정·폐기할 것인가?

## 핵심 원리

### 목적 있는 모션

전환의 출발·도착, 계층, 진행, 피드백을 설명하는 기능적 목적이 있어야 한다.

### 연속성과 인과

사용자 행동과 가까운 시점·위치에서 반응하고 객체가 어디서 왔고 어디로 갔는지 이해하게 한다.

### 절제와 속도

빈도 높은 과업과 전문가 도구는 짧고 방해 없는 모션을 사용하며 완료를 기다리게 하지 않는다.

### 감소된 모션

사용자 환경 설정을 존중하고 큰 이동·확대·회전·시차를 페이드나 즉시 전환 등 의미가 유지되는 대안으로 바꾼다.

### 정지 가능성

자동 재생·반복·움직이는 콘텐츠는 일시정지·정지·숨김과 시간 제어를 제공한다.

## 규범적 요구사항

> **MUST**는 위반 시 사용자 과업·안전·접근성·신뢰 또는 검증 가능성이 실질적으로 훼손되는 요구사항이다.  
> **SHOULD**는 특별한 맥락과 근거가 있을 때만 예외를 허용하는 강한 권고다.  
> **MAY**는 선택 가능한 구현 방식이며, 대안의 사용자 결과와 위험을 기록해야 한다.

### MUST

- **MUST:** 각 애니메이션의 전달 목적과 모션 없이도 유지해야 할 정보·상태를 정의한다.
- **MUST:** 운영체제·브라우저의 감소된 모션 선호를 감지하고 의미를 보존하는 대체 전환을 제공한다.
- **MUST:** 자동 재생·반복·깜빡임·큰 시차·급격한 확대·회전을 접근성 위험 관점에서 제한한다.
- **MUST:** 애니메이션 중에도 키보드 입력, 포커스, 클릭, 상태 업데이트가 지연·차단되지 않게 한다.
- **MUST:** 로딩 지연이나 성능 문제를 애니메이션으로 숨기지 않고 실제 성능과 상태를 측정한다.

### SHOULD

- **SHOULD:** 같은 의미와 공간 관계에는 일관된 모션 토큰과 방향을 사용한다.
- **SHOULD:** 사용자가 반복 수행하는 흐름은 모션 단축·건너뛰기 또는 설정을 고려한다.
- **SHOULD:** 저사양 기기와 배터리·네트워크 제약에서 프레임 저하와 입력 지연을 테스트한다.
- **SHOULD:** 모션 사양에 지속시간뿐 아니라 트리거, 시작·종료 상태, 중단, 역전, 감소 모드 동작을 포함한다.

### MAY

- **MAY:** 프로젝트의 플랫폼·도메인·조직 제약이 정당화하면 다른 패턴을 선택할 수 있다. 단, 사용자 결과, 접근성, 위해, 되돌리기 가능성, 검증 계획을 결정 로그에 남긴다.
- **MAY:** 검증 비용을 줄이기 위해 충실도와 방법을 조정할 수 있다. 단, 조정으로 답할 수 없게 된 질문과 미검증 영역을 명시한다.

## 설계·실행 절차

1. 상태 변화와 공간 관계 중 모션이 실제로 설명해야 할 부분을 식별한다.
2. 모션 없음·기본 모션·감소 모션의 결과 상태와 의미를 먼저 정의한다.
3. 트리거, 지속시간, 지연, 이징, 방향, 중단·역전, 입력 가능성을 명세한다.
4. 반복·자동 재생·큰 이동·깜빡임 위험을 제거하거나 제어를 제공한다.
5. 다양한 설정·기기·보조기술에서 이해·불편·성능을 테스트한다.
6. 이탈·멀미 신고·설정 사용·프레임·입력 지연으로 모션을 개선한다.

## 예외·극단 상황

- 지도·3D·데이터 시각화에서 이동과 확대가 핵심 상호작용인 경우
- 실시간 경고나 상태 변화가 매우 자주 발생하는 대시보드
- 게임화·브랜드 표현과 핵심 과업이 같은 화면에 있는 경우
- 모션 중 사용자가 즉시 반대 방향 행동을 수행하는 경우
- 원격 데스크톱·저사양 기기에서 애니메이션이 크게 끊기는 경우

## 실패 패턴과 교정

| 실패 패턴 | 교정 방법 |
|---|---|
| 감소된 모션에서 모든 전환을 제거해 상태 변화가 사라진다. | 큰 움직임을 줄이되 텍스트·페이드·즉시 상태 변화로 의미를 유지한다. |
| 애니메이션이 끝나야 다음 행동을 할 수 있다. | 입력과 포커스를 즉시 허용하고 모션을 취소·완료 가능한 상태로 만든다. |
| 로딩 스피너를 화려하게 만들어 지연을 감춘다. | 작업 상태와 예상·대안을 전달하고 실제 지연을 줄인다. |
| 모든 화면 전환에 같은 큰 슬라이드를 사용한다. | 공간 관계와 과업 빈도에 맞춰 모션을 절제한다. |
| 자동 재생을 멈출 수 없다. | 일시정지·정지·숨김과 사용자 선호를 제공한다. |

## 검증 방법

1. 감소된 모션·기본 모션·모션 비활성 상태에서 같은 과업 의미와 결과가 유지되는지 확인한다.
2. 키보드로 빠르게 연속 조작해 전환 중 포커스·상태·입력이 안정적인지 테스트한다.
3. 전정 장애·주의 민감성이 있는 사용자와 큰 이동·시차·자동 재생 불편을 평가한다.
4. 저사양 기기에서 프레임, 입력 응답, 레이아웃 안정성과 배터리 영향을 측정한다.

## 에이전트 적용 규칙

- 모션 제안에는 목적, 트리거, 종료 상태, 입력 가능, 감소 모드 대안을 함께 작성한다.
- 특정 지속시간을 절대 기준으로 제시하지 말고 과업·기기·반복 빈도로 검증한다.
- 장식 모션은 기본값이 아니라 제거 가능한 선택으로 본다.
- 입력에 근거가 없으면 사실을 보충하지 말고 가정, 확인 질문 또는 검증 과제로 표시한다.
- 정적 이미지·텍스트만 제공된 경우 키보드, 포커스, 보조기술, 성능, 동적 상태를 통과했다고 단정하지 않는다.
- 권고를 제시할 때 사용자 영향, 트레이드오프, 검증 방법을 함께 적는다.

## 범위와 근거 수준

이 문서는 공개 표준, 공공 서비스 가이드, 제품 디자인 시스템, UX 연구 자료를 교차해 재구성한 독립적인 한국어 실무 가이드다. 특정 출처의 원문을 대체하거나 특정 조직의 승인·제휴를 의미하지 않는다.

규범 표준에 직접 근거한 요구사항과 여러 출처를 종합한 실무 권고를 구분해 사용한다. 법률·규제 준수, 현재 제품 기능, 최신 브라우저·보조기술 지원, 성능 지표와 임계값처럼 변할 수 있는 사항은 적용 시점의 공식 자료와 실제 구현으로 다시 확인한다.

> **최신성 주의:** 이 가이드는 시간에 따라 정의·도구·권고가 바뀔 수 있는 내용을 포함한다. 현재 공식 문서와 운영 데이터를 확인하지 않은 수치·기능·임계값은 미검증으로 표시한다.
