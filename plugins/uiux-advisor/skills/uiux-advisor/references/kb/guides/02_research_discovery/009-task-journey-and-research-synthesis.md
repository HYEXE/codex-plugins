# 과업·여정·리서치 합성

## 한 문장 원칙

연구 조각을 예쁜 지도에 배치하는 데 그치지 말고 사용자 목표, 사건의 순서, 장벽, 감정, 채널, 책임, 증거를 의사결정 가능한 구조로 합성한다.

## 적용 상황

인터뷰·분석·지원 문의가 여러 파일에 흩어져 있거나 여정 지도가 일반적 단계와 감정 곡선만 보여 실제 설계 우선순위를 결정하지 못할 때 사용한다.

## 이 가이드가 답하는 결정

1. 이 문제에서 반드시 지켜야 할 사용자 결과와 품질 경계는 무엇인가?
2. 어떤 상태·맥락·사용자 조건을 포함해야 설계가 실제 환경에서 무너지지 않는가?
3. 어떤 증거와 검증 방법으로 이 결정을 승인·수정·폐기할 것인가?

## 핵심 원리

### 과업 중심 단위

제품 화면이 아니라 사용자가 외부 세계에서 달성하려는 과업과 시작·종료 조건을 합성 단위로 삼는다.

### 시간과 인과 보존

관찰을 주제별로 자를 때 사건 순서와 장벽의 원인·결과 관계가 사라지지 않게 한다.

### 근거 추적성

각 통찰이 어떤 세션, 로그, 지원 사례, 문서에서 나왔는지 추적 가능해야 한다.

### 패턴과 반례

빈도만이 아니라 위해, 구조적 배제, 반복 조건, 반례를 함께 기록한다.

### 서비스 책임

사용자 행동뿐 아니라 조직 프로세스, 정책, 시스템, 다른 채널이 경험에 미치는 책임을 표시한다.

## 규범적 요구사항

> **MUST**는 위반 시 사용자 과업·안전·접근성·신뢰 또는 검증 가능성이 실질적으로 훼손되는 요구사항이다.  
> **SHOULD**는 특별한 맥락과 근거가 있을 때만 예외를 허용하는 강한 권고다.  
> **MAY**는 선택 가능한 구현 방식이며, 대안의 사용자 결과와 위험을 기록해야 한다.

### MUST

- **MUST:** 합성의 범위, 대상 사용자, 과업 시작·종료, 포함 채널과 시간 범위를 명시한다.
- **MUST:** 관찰 사실, 참가자 해석, 연구자 해석, 설계 기회를 별도 필드로 구분한다.
- **MUST:** 각 통찰에 근거 출처와 확신 수준, 반례 또는 빈틈을 연결한다.
- **MUST:** 여정의 각 단계에서 사용자 목표, 정보 필요, 행동, 장벽, 결과, 책임 주체를 기록한다.
- **MUST:** 감정 곡선을 근거 없이 꾸미지 않고 관찰된 감정·스트레스 신호만 표시한다.

### SHOULD

- **SHOULD:** 과업 성공·실패·우회 경로를 함께 모델링한다.
- **SHOULD:** 문제의 빈도, 심각도, 해결 가능성, 전략적 중요도로 기회를 우선순위화한다.
- **SHOULD:** 사용자군별 차이가 행동·맥락에 근거하는지 확인하고 불필요한 페르소나 분리를 피한다.
- **SHOULD:** 지도에는 결정, 책임자, 다음 검증 항목을 연결해 살아 있는 운영 도구로 사용한다.

### MAY

- **MAY:** 프로젝트의 플랫폼·도메인·조직 제약이 정당화하면 다른 패턴을 선택할 수 있다. 단, 사용자 결과, 접근성, 위해, 되돌리기 가능성, 검증 계획을 결정 로그에 남긴다.
- **MAY:** 검증 비용을 줄이기 위해 충실도와 방법을 조정할 수 있다. 단, 조정으로 답할 수 없게 된 질문과 미검증 영역을 명시한다.

## 설계·실행 절차

1. 연구 자료를 동일한 과업·시간·행동 단위로 정규화한다.
2. 사례별 타임라인을 먼저 만든 뒤 공통 단계와 변이를 비교한다.
3. 장벽, 성공 요인, 우회, 정보 요구, 감정 신호, 시스템 책임을 코딩한다.
4. 패턴·반례·빈틈을 근거 링크와 함께 통찰 문장으로 만든다.
5. 기회 가설을 사용자 결과와 조직 제약에 연결해 우선순위화한다.
6. 결정과 후속 연구가 발생할 때 지도·근거·버전을 갱신한다.

## 예외·극단 상황

- 온라인·전화·오프라인·문서가 섞인 다채널 서비스
- 여러 사람이 한 과업을 순차적으로 수행하는 협업·승인 흐름
- 반복 사용이 숙련과 자동화를 만들어 초보·전문가 여정이 크게 다른 경우
- 장기 여정에서 정책·생활 사건이 제품 사용보다 큰 영향을 주는 경우
- 표본이 적지만 위해가 큰 배제·실패 사례가 있는 경우

## 실패 패턴과 교정

| 실패 패턴 | 교정 방법 |
|---|---|
| 여정 단계를 제품 메뉴 구조로 만든다. | 사용자 목표와 사건을 기준으로 제품 밖 단계까지 포함한다. |
| 모든 사용자에게 하나의 평균 여정을 적용한다. | 맥락·권한·숙련도·채널에 따른 주요 변이를 별도 경로로 표시한다. |
| 포스트잇 개수로 통찰 빈도를 판단한다. | 세션·사용자 단위 중복을 제거하고 심각도와 구조적 위해를 함께 본다. |
| 통찰과 아이디어를 섞는다. | 증거 기반 관찰, 해석, 기회, 해결책을 단계적으로 분리한다. |
| 지도를 발표 후 방치한다. | 결정 로그, 책임자, 검증 상태, 갱신 주기를 연결한다. |

## 검증 방법

1. 원자료에서 합성 통찰까지 역추적 가능한지 샘플 검사를 한다.
2. 현장 담당자와 사용자가 주요 단계·장벽·우회를 실제 경험으로 인식하는지 검토한다.
3. 반례와 빠진 사용자·채널·실패 상태를 별도 워크숍에서 찾는다.
4. 우선순위가 단순 빈도가 아니라 결과와 위해를 반영하는지 확인한다.

## 인수 기준

- [ ] 합성의 범위, 대상 사용자, 과업 시작·종료, 포함 채널과 시간 범위를 명시한다.
- [ ] 관찰 사실, 참가자 해석, 연구자 해석, 설계 기회를 별도 필드로 구분한다.
- [ ] 각 통찰에 근거 출처와 확신 수준, 반례 또는 빈틈을 연결한다.
- [ ] 여정의 각 단계에서 사용자 목표, 정보 필요, 행동, 장벽, 결과, 책임 주체를 기록한다.
- [ ] 감정 곡선을 근거 없이 꾸미지 않고 관찰된 감정·스트레스 신호만 표시한다.
- [ ] 원자료에서 합성 통찰까지 역추적 가능한지 샘플 검사를 한다.
- [ ] 현장 담당자와 사용자가 주요 단계·장벽·우회를 실제 경험으로 인식하는지 검토한다.
- [ ] 반례와 빠진 사용자·채널·실패 상태를 별도 워크숍에서 찾는다.

## 에이전트 적용 규칙

- 여정 지도를 요청받으면 단계명만 생성하지 말고 목표, 장벽, 증거, 책임, 성공·실패 경로를 포함한다.
- 근거가 제공되지 않은 감정 곡선과 페르소나 세부를 꾸며내지 않는다.
- 통찰마다 근거 수준과 다음 검증 질문을 표시한다.
- 입력에 근거가 없으면 사실을 보충하지 말고 가정, 확인 질문 또는 검증 과제로 표시한다.
- 정적 이미지·텍스트만 제공된 경우 키보드, 포커스, 보조기술, 성능, 동적 상태를 통과했다고 단정하지 않는다.
- 권고를 제시할 때 사용자 영향, 트레이드오프, 검증 방법을 함께 적는다.

## 범위와 근거 수준

이 문서는 공개 표준, 공공 서비스 가이드, 제품 디자인 시스템, UX 연구 자료를 교차해 재구성한 독립적인 한국어 실무 가이드다. 특정 출처의 원문을 대체하거나 특정 조직의 승인·제휴를 의미하지 않는다.

규범 표준에 직접 근거한 요구사항과 여러 출처를 종합한 실무 권고를 구분해 사용한다. 법률·규제 준수, 현재 제품 기능, 최신 브라우저·보조기술 지원, 성능 지표와 임계값처럼 변할 수 있는 사항은 적용 시점의 공식 자료와 실제 구현으로 다시 확인한다.
