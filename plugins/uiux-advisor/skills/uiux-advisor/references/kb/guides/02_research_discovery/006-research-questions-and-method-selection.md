# 리서치 질문과 방법 선택

## 한 문장 원칙

방법을 먼저 고르지 말고 어떤 결정을 위해 무엇을 알아야 하는지, 행동과 태도 중 무엇을 관찰해야 하는지부터 정한다.

## 적용 상황

‘인터뷰를 하자’, ‘설문을 돌리자’, ‘사용성 테스트를 하자’처럼 방법이 관성적으로 정해졌거나 하나의 연구로 탐색·평가·측정을 모두 해결하려 할 때 사용한다.

## 이 가이드가 답하는 결정

1. 이 문제에서 반드시 지켜야 할 사용자 결과와 품질 경계는 무엇인가?
2. 어떤 상태·맥락·사용자 조건을 포함해야 설계가 실제 환경에서 무너지지 않는가?
3. 어떤 증거와 검증 방법으로 이 결정을 승인·수정·폐기할 것인가?

## 핵심 원리

### 결정에서 질문으로

연구 질문은 흥미로운 정보 수집이 아니라 바뀔 수 있는 제품 결정을 뒷받침해야 한다.

### 태도와 행동 분리

사람이 말하는 선호·기억과 실제 과업 행동은 다를 수 있으므로 질문에 맞는 관찰 수준을 선택한다.

### 정성·정량의 역할

정성은 이유와 패턴을 발견하고 정량은 범위·빈도·차이를 추정한다. 둘을 단순 우열로 비교하지 않는다.

### 생성·평가 구분

문제·기회를 찾는 생성 연구와 설계안의 사용성을 검증하는 평가 연구는 과업과 진행 방식이 다르다.

### 한계의 명시

표본, 모집, 도구, 환경, 분석 방법이 어떤 결론을 허용하고 금지하는지 연구 전에 기록한다.

## 규범적 요구사항

> **MUST**는 위반 시 사용자 과업·안전·접근성·신뢰 또는 검증 가능성이 실질적으로 훼손되는 요구사항이다.  
> **SHOULD**는 특별한 맥락과 근거가 있을 때만 예외를 허용하는 강한 권고다.  
> **MAY**는 선택 가능한 구현 방식이며, 대안의 사용자 결과와 위험을 기록해야 한다.

### MUST

- **MUST:** 연구가 바꿀 의사결정, 의사결정 기한, 이해관계자, 현재 가정을 명시한다.
- **MUST:** 연구 질문마다 필요한 증거가 태도·행동, 정성·정량, 자연 맥락·통제 환경 중 어디에 속하는지 분류한다.
- **MUST:** 질문에 맞지 않는 방법으로 인과·대표성·실제 행동을 과장하지 않는다.
- **MUST:** 모집 기준, 제외 기준, 표본의 빈틈과 접근성 요구를 계획에 포함한다.
- **MUST:** 개인정보·동의·보상·민감 주제·데이터 보존 절차를 정의한다.

### SHOULD

- **SHOULD:** 핵심 질문과 있으면 좋은 질문을 구분해 연구 범위를 통제한다.
- **SHOULD:** 하나의 방법에서 얻은 결과를 다른 데이터로 삼각 검증한다.
- **SHOULD:** 파일럿으로 질문, 과업, 시간, 도구, 접근성 문제를 확인한다.
- **SHOULD:** 결과 공유 전에 증거, 해석, 권고, 미해결 질문을 분리한다.

### MAY

- **MAY:** 프로젝트의 플랫폼·도메인·조직 제약이 정당화하면 다른 패턴을 선택할 수 있다. 단, 사용자 결과, 접근성, 위해, 되돌리기 가능성, 검증 계획을 결정 로그에 남긴다.
- **MAY:** 검증 비용을 줄이기 위해 충실도와 방법을 조정할 수 있다. 단, 조정으로 답할 수 없게 된 질문과 미검증 영역을 명시한다.

## 설계·실행 절차

1. 결정 문장과 가장 위험한 가정을 작성한다.
2. 가정별로 필요한 관찰 또는 측정 가능한 증거를 정의한다.
3. 방법 매트릭스로 인터뷰, 현장 관찰, 사용성 테스트, 분석, 설문, 실험을 비교한다.
4. 표본·환경·도구·윤리·접근성 제약에 맞게 방법을 조합한다.
5. 성공·중단·분석 기준과 결론의 한계를 사전 기록한다.
6. 연구 후 의사결정이 실제로 변경되었는지와 다음 질문을 기록한다.

## 예외·극단 상황

- 사용자에게 직접 접근할 수 없어 지원 담당자·로그·2차 연구에 의존해야 하는 경우
- 매우 드문 고위험 사건이라 표본을 충분히 모을 수 없는 경우
- 민감한 주제에서 말과 행동을 직접 관찰하기 어려운 경우
- 조직 고객의 구매자와 실제 사용자가 다른 B2B 연구
- 현장 환경을 재현하기 어려운 연결성·소음·보조기술·긴급 상황

## 실패 패턴과 교정

| 실패 패턴 | 교정 방법 |
|---|---|
| 인터뷰로 인터페이스 사용성을 검증한다. | 대표 과업을 실제로 수행하게 하고 행동과 오류를 관찰한다. |
| 작은 정성 표본의 비율을 모집단 수치처럼 제시한다. | 패턴·가설로 표현하고 범위를 추정하려면 적절한 정량 방법을 추가한다. |
| 설문에서 사용자가 미래에 할 행동을 정확히 예측한다고 본다. | 실제 행동 데이터나 과업 관찰로 보완한다. |
| 연구 질문이 너무 많아 핵심 결정을 놓친다. | 의사결정 영향과 위험도로 질문을 줄이고 후속 연구를 분리한다. |
| 부정적 결과를 참가자 문제로 돌린다. | 과업, 프로토타입, 진행, 모집, 환경의 대안 설명을 검토한다. |

## 검증 방법

1. 각 연구 질문 옆에 결과가 어떤 결정을 어떻게 바꿀지 적을 수 있는지 확인한다.
2. 선택한 방법이 실제로 질문에 필요한 행동·태도·빈도·원인을 포착하는지 동료 검토한다.
3. 파일럿 참가자가 과업과 질문을 의도한 대로 이해하는지 확인한다.
4. 연구 결과에서 허용되는 주장과 허용되지 않는 주장을 명시한다.

## 인수 기준

- [ ] 연구가 바꿀 의사결정, 의사결정 기한, 이해관계자, 현재 가정을 명시한다.
- [ ] 연구 질문마다 필요한 증거가 태도·행동, 정성·정량, 자연 맥락·통제 환경 중 어디에 속하는지 분류한다.
- [ ] 질문에 맞지 않는 방법으로 인과·대표성·실제 행동을 과장하지 않는다.
- [ ] 모집 기준, 제외 기준, 표본의 빈틈과 접근성 요구를 계획에 포함한다.
- [ ] 개인정보·동의·보상·민감 주제·데이터 보존 절차를 정의한다.
- [ ] 각 연구 질문 옆에 결과가 어떤 결정을 어떻게 바꿀지 적을 수 있는지 확인한다.
- [ ] 선택한 방법이 실제로 질문에 필요한 행동·태도·빈도·원인을 포착하는지 동료 검토한다.
- [ ] 파일럿 참가자가 과업과 질문을 의도한 대로 이해하는지 확인한다.

## 에이전트 적용 규칙

- 사용자가 방법만 요청해도 우선 연구 결정과 질문을 역산해 제시한다.
- 표본 수를 맥락 없이 단정하지 말고 연구 목적, 변이, 위험, 모집 가능성에 따라 설명한다.
- 연구 결과를 사실·해석·권고·한계로 구분해 출력한다.
- 입력에 근거가 없으면 사실을 보충하지 말고 가정, 확인 질문 또는 검증 과제로 표시한다.
- 정적 이미지·텍스트만 제공된 경우 키보드, 포커스, 보조기술, 성능, 동적 상태를 통과했다고 단정하지 않는다.
- 권고를 제시할 때 사용자 영향, 트레이드오프, 검증 방법을 함께 적는다.

## 범위와 근거 수준

이 문서는 공개 표준, 공공 서비스 가이드, 제품 디자인 시스템, UX 연구 자료를 교차해 재구성한 독립적인 한국어 실무 가이드다. 특정 출처의 원문을 대체하거나 특정 조직의 승인·제휴를 의미하지 않는다.

규범 표준에 직접 근거한 요구사항과 여러 출처를 종합한 실무 권고를 구분해 사용한다. 법률·규제 준수, 현재 제품 기능, 최신 브라우저·보조기술 지원, 성능 지표와 임계값처럼 변할 수 있는 사항은 적용 시점의 공식 자료와 실제 구현으로 다시 확인한다.
