# 설문과 정량 리서치

## 한 문장 원칙

측정하려는 구성개념과 의사결정을 먼저 정의하고, 표본·문항·척도·분석이 허용하는 범위 안에서만 수치를 해석한다.

## 적용 상황

만족도, 인식, 빈도, 세그먼트 차이, 문제 규모를 추정해야 하거나 설문 결과가 ‘사용자 전체의 의견’처럼 과도하게 일반화될 위험이 있을 때 사용한다.

## 이 가이드가 답하는 결정

1. 이 문제에서 반드시 지켜야 할 사용자 결과와 품질 경계는 무엇인가?
2. 어떤 상태·맥락·사용자 조건을 포함해야 설계가 실제 환경에서 무너지지 않는가?
3. 어떤 증거와 검증 방법으로 이 결정을 승인·수정·폐기할 것인가?

## 핵심 원리

### 구성개념의 명료성

만족, 신뢰, 용이성, 충성도처럼 보이지 않는 개념은 한 문항으로 충분하지 않을 수 있으며 무엇을 측정하는지 정의해야 한다.

### 표본과 모집 프레임

응답자는 전체 사용자와 다를 수 있다. 초대 경로, 응답률, 비응답 편향, 활성 사용자 편향을 기록한다.

### 문항 중립성

한 문항에 한 개념만 묻고, 유도·가정·전문용어·이중 부정을 피하며 응답 가능한 기간과 맥락을 제시한다.

### 척도 일관성

척도 방향, 레이블, 중립·해당 없음 선택지, 순서 효과를 일관되게 설계한다.

### 불확실성 표현

표본 오차뿐 아니라 측정 오류와 편향을 포함해 결과 범위와 한계를 설명한다.

## 규범적 요구사항

> **MUST**는 위반 시 사용자 과업·안전·접근성·신뢰 또는 검증 가능성이 실질적으로 훼손되는 요구사항이다.  
> **SHOULD**는 특별한 맥락과 근거가 있을 때만 예외를 허용하는 강한 권고다.  
> **MAY**는 선택 가능한 구현 방식이며, 대안의 사용자 결과와 위험을 기록해야 한다.

### MUST

- **MUST:** 설문이 답할 연구 질문과 그 결과가 바꿀 결정을 명시한다.
- **MUST:** 대상 모집단, 모집 경로, 포함·제외 기준, 표본 특성, 응답률을 기록한다.
- **MUST:** 문항을 배포 전 인지 인터뷰 또는 파일럿으로 검토한다.
- **MUST:** 상관관계를 원인으로 표현하거나 작은 차이를 실질적 차이로 과장하지 않는다.
- **MUST:** 민감 정보는 최소 수집하고 익명성·비밀보장 범위를 정확히 설명한다.

### SHOULD

- **SHOULD:** 검증된 척도를 사용할 때 대상 언어·문화·맥락에서의 적합성을 확인한다.
- **SHOULD:** 행동 로그나 정성 연구와 연결해 수치의 이유를 해석한다.
- **SHOULD:** 분석 계획, 제외 규칙, 세그먼트 비교를 데이터 확인 전에 정한다.
- **SHOULD:** 접근 가능한 설문 도구, 키보드 사용, 오류 복구, 모바일 길이를 검증한다.

### MAY

- **MAY:** 프로젝트의 플랫폼·도메인·조직 제약이 정당화하면 다른 패턴을 선택할 수 있다. 단, 사용자 결과, 접근성, 위해, 되돌리기 가능성, 검증 계획을 결정 로그에 남긴다.
- **MAY:** 검증 비용을 줄이기 위해 충실도와 방법을 조정할 수 있다. 단, 조정으로 답할 수 없게 된 질문과 미검증 영역을 명시한다.

## 설계·실행 절차

1. 측정할 구성개념과 행동·태도 지표를 정의한다.
2. 모집단과 표본 프레임을 정하고 예상 편향을 기록한다.
3. 필수 문항만 작성하고 논리 분기와 응답 부담을 줄인다.
4. 인지 인터뷰와 파일럿으로 이해·척도·기술 문제를 수정한다.
5. 사전 분석 계획에 결측, 이상치, 가중, 다중 비교와 중단 기준을 포함한다.
6. 결과를 효과 크기, 불확실성, 표본 한계, 정성 맥락과 함께 보고한다.

## 예외·극단 상황

- 로그인하지 않은 사용자나 이탈 사용자를 모집하기 어려운 경우
- 소수 집단의 프라이버시와 통계적 안정성이 충돌하는 경우
- 다국어 번역이 개념과 척도 의미를 바꾸는 경우
- 인센티브가 응답 품질이나 중복 참여에 영향을 주는 경우
- 장기간 추적에서 생존자 편향과 응답 피로가 누적되는 경우

## 실패 패턴과 교정

| 실패 패턴 | 교정 방법 |
|---|---|
| 열성 사용자 대상 설문을 전체 사용자 의견으로 일반화한다. | 모집 프레임을 밝히고 이탈·비활성 사용자 데이터로 보완한다. |
| ‘빠르고 쉬웠나요?’처럼 두 개념을 한 문항에 묻는다. | 속도와 용이성을 별도 문항으로 분리한다. |
| 평균만 보고 분포와 극단 응답을 숨긴다. | 분포, 구간, 세그먼트, 응답 수와 불확실성을 함께 제시한다. |
| 응답자의 미래 행동 의향을 실제 행동처럼 해석한다. | 의향으로 명시하고 가능한 경우 실제 행동 데이터로 검증한다. |
| 설문이 너무 길어 후반 품질이 떨어진다. | 결정에 직접 필요하지 않은 문항을 제거하고 길이·중단률을 측정한다. |

## 검증 방법

1. 인지 인터뷰에서 참가자가 각 문항을 어떻게 해석하고 답을 찾는지 관찰한다.
2. 파일럿에서 완료 시간, 중단 지점, 무응답, 동일 응답 패턴을 검토한다.
3. 표본 특성을 모집단 또는 이용자 데이터와 비교해 편향을 확인한다.
4. 결과 문장마다 추론 범위와 대안 설명을 동료가 검토한다.

## 인수 기준

- [ ] 설문이 답할 연구 질문과 그 결과가 바꿀 결정을 명시한다.
- [ ] 대상 모집단, 모집 경로, 포함·제외 기준, 표본 특성, 응답률을 기록한다.
- [ ] 문항을 배포 전 인지 인터뷰 또는 파일럿으로 검토한다.
- [ ] 상관관계를 원인으로 표현하거나 작은 차이를 실질적 차이로 과장하지 않는다.
- [ ] 민감 정보는 최소 수집하고 익명성·비밀보장 범위를 정확히 설명한다.
- [ ] 인지 인터뷰에서 참가자가 각 문항을 어떻게 해석하고 답을 찾는지 관찰한다.
- [ ] 파일럿에서 완료 시간, 중단 지점, 무응답, 동일 응답 패턴을 검토한다.
- [ ] 표본 특성을 모집단 또는 이용자 데이터와 비교해 편향을 확인한다.

## 에이전트 적용 규칙

- 설문 문항을 만들 때 측정 목적, 기간, 단일 개념, 중립성, 해당 없음을 확인한다.
- 표본 크기를 근거 없이 숫자로 제시하지 말고 기대 효과, 정밀도, 모집 프레임, 분석 계획을 요구한다.
- 통계 결과가 제공되지 않았다면 수치나 유의성을 만들어내지 않는다.
- 입력에 근거가 없으면 사실을 보충하지 말고 가정, 확인 질문 또는 검증 과제로 표시한다.
- 정적 이미지·텍스트만 제공된 경우 키보드, 포커스, 보조기술, 성능, 동적 상태를 통과했다고 단정하지 않는다.
- 권고를 제시할 때 사용자 영향, 트레이드오프, 검증 방법을 함께 적는다.

## 범위와 근거 수준

이 문서는 공개 표준, 공공 서비스 가이드, 제품 디자인 시스템, UX 연구 자료를 교차해 재구성한 독립적인 한국어 실무 가이드다. 특정 출처의 원문을 대체하거나 특정 조직의 승인·제휴를 의미하지 않는다.

규범 표준에 직접 근거한 요구사항과 여러 출처를 종합한 실무 권고를 구분해 사용한다. 법률·규제 준수, 현재 제품 기능, 최신 브라우저·보조기술 지원, 성능 지표와 임계값처럼 변할 수 있는 사항은 적용 시점의 공식 자료와 실제 구현으로 다시 확인한다.
