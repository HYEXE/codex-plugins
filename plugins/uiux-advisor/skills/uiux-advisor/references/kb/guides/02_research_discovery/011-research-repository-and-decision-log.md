# 리서치 리포지터리와 결정 로그

## 한 문장 원칙

원자료, 관찰, 통찰, 권고, 결정, 결과를 분리하고 추적 가능하게 연결해 연구가 재사용되면서도 맥락과 개인정보를 잃지 않게 한다.

## 적용 상황

같은 질문을 반복 연구하거나 보고서 링크만 쌓여 찾기 어렵고, 오래된 통찰이 현재 사실처럼 재사용되며, 디자인 결정의 근거와 결과가 연결되지 않을 때 사용한다.

## 이 가이드가 답하는 결정

1. 이 문제에서 반드시 지켜야 할 사용자 결과와 품질 경계는 무엇인가?
2. 어떤 상태·맥락·사용자 조건을 포함해야 설계가 실제 환경에서 무너지지 않는가?
3. 어떤 증거와 검증 방법으로 이 결정을 승인·수정·폐기할 것인가?

## 핵심 원리

### 계층 분리

원자료·사실 관찰·해석·통찰·기회·결정은 서로 다른 신뢰 수준과 수명을 가진다.

### 메타데이터와 맥락

날짜, 사용자군, 과업, 제품 버전, 방법, 표본, 제한, 소유자 없이는 재사용 가능성이 낮다.

### 추적성과 반례

결정에서 근거로, 근거에서 원자료로 역추적하고 반례와 폐기된 해석도 보존한다.

### 수명과 최신성

정책·제품·시장·사용자 행동이 바뀌면 통찰의 유효성이 달라진다. 검토일과 상태를 관리한다.

### 최소 접근

민감 원자료는 필요한 사람만 접근하고 검색 가능한 합성 정보와 분리한다.

## 규범적 요구사항

> **MUST**는 위반 시 사용자 과업·안전·접근성·신뢰 또는 검증 가능성이 실질적으로 훼손되는 요구사항이다.  
> **SHOULD**는 특별한 맥락과 근거가 있을 때만 예외를 허용하는 강한 권고다.  
> **MAY**는 선택 가능한 구현 방식이며, 대안의 사용자 결과와 위험을 기록해야 한다.

### MUST

- **MUST:** 각 연구 항목에 날짜, 목적, 방법, 표본, 과업, 제품 버전, 한계, 소유자, 상태를 기록한다.
- **MUST:** 직접 관찰·발언과 연구자의 해석·권고를 구조적으로 구분한다.
- **MUST:** 통찰·결정마다 근거 링크, 반례, 확신 수준, 검토 예정일을 연결한다.
- **MUST:** 동의 범위와 보존 기간에 따라 영상·음성·식별 정보의 접근과 삭제를 관리한다.
- **MUST:** 오래되거나 반증된 통찰을 삭제해 흔적을 없애기보다 폐기 상태와 이유를 기록한다.

### SHOULD

- **SHOULD:** 사용자 목표·과업·장벽·채널·세그먼트·제품 영역의 공통 분류 체계를 운영한다.
- **SHOULD:** 제품 요구사항·실험·디자인 시스템 변경과 연구 근거를 양방향 연결한다.
- **SHOULD:** 검색 결과에 최신성, 근거 종류, 표본 범위, 신뢰 수준이 보이게 한다.
- **SHOULD:** 정기적으로 중복·상충 통찰과 근거 공백을 검토해 연구 로드맵에 반영한다.

### MAY

- **MAY:** 프로젝트의 플랫폼·도메인·조직 제약이 정당화하면 다른 패턴을 선택할 수 있다. 단, 사용자 결과, 접근성, 위해, 되돌리기 가능성, 검증 계획을 결정 로그에 남긴다.
- **MAY:** 검증 비용을 줄이기 위해 충실도와 방법을 조정할 수 있다. 단, 조정으로 답할 수 없게 된 질문과 미검증 영역을 명시한다.

## 설계·실행 절차

1. 현재 자료와 접근 권한, 민감도, 중복을 인벤토리한다.
2. 자료 계층과 필수 메타데이터, 상태, 분류 체계를 정의한다.
3. 기존 연구를 최소 단위로 이전하면서 원문 링크와 맥락을 보존한다.
4. 통찰·결정·결과를 연결하는 템플릿과 리뷰 절차를 만든다.
5. 검색·권한·보존·검토 주기를 운영하고 사용 로그를 확인한다.
6. 결정 결과와 새 근거로 기존 통찰의 상태를 갱신한다.

## 예외·극단 상황

- 여러 국가의 개인정보·보존 규칙이 다른 글로벌 조직
- 외부 연구 업체와 원자료 소유권·재사용 권한이 다른 경우
- 소수 사용자군의 인용만으로 신원을 추정할 수 있는 경우
- 제품 이름·정보구조가 바뀌어 과거 태그가 현재 구조와 맞지 않는 경우
- AI 검색·요약 기능이 민감 원자료에 접근하는 경우

## 실패 패턴과 교정

| 실패 패턴 | 교정 방법 |
|---|---|
| PDF 보고서만 업로드한다. | 결정에 재사용할 수 있는 구조화된 관찰·통찰·메타데이터를 함께 저장한다. |
| 태그를 자유 입력해 같은 개념이 여러 이름으로 분산된다. | 통제 어휘와 동의어를 관리하고 주기적으로 정규화한다. |
| 오래된 연구를 최신 사실로 인용한다. | 제품 버전·수집일·검토일·현재 상태를 검색 결과에 표시한다. |
| 원자료를 모든 팀에 공개한다. | 검색 가능한 합성 정보와 최소 권한 원자료 저장소를 분리한다. |
| 결정 이후 결과를 기록하지 않는다. | 출시·실험·운영 결과를 결정 로그에 연결해 근거의 예측력을 평가한다. |

## 검증 방법

1. 대표 질문으로 검색해 관련 연구를 2분 안에 찾고 범위·최신성·한계를 이해할 수 있는지 테스트한다.
2. 무작위 결정 5개를 근거와 원자료까지 역추적한다.
3. 접근 권한과 보존 기간을 정기 감사하고 삭제 요청 흐름을 시험한다.
4. 사용되지 않는 태그·중복 통찰·검토 기한 초과 항목을 지표로 관리한다.

## 에이전트 적용 규칙

- 리포지터리 요약 시 오래된 자료와 현재 자료를 구분하고 출처·범위·한계를 유지한다.
- 원자료에 없는 인용·참가자 특성·결론을 생성하지 않는다.
- 상충하는 근거는 하나로 합치지 말고 조건과 차이를 드러낸다.
- 입력에 근거가 없으면 사실을 보충하지 말고 가정, 확인 질문 또는 검증 과제로 표시한다.
- 정적 이미지·텍스트만 제공된 경우 키보드, 포커스, 보조기술, 성능, 동적 상태를 통과했다고 단정하지 않는다.
- 권고를 제시할 때 사용자 영향, 트레이드오프, 검증 방법을 함께 적는다.

## 범위와 근거 수준

이 문서는 공개 표준, 공공 서비스 가이드, 제품 디자인 시스템, UX 연구 자료를 교차해 재구성한 독립적인 한국어 실무 가이드다. 특정 출처의 원문을 대체하거나 특정 조직의 승인·제휴를 의미하지 않는다.

규범 표준에 직접 근거한 요구사항과 여러 출처를 종합한 실무 권고를 구분해 사용한다. 법률·규제 준수, 현재 제품 기능, 최신 브라우저·보조기술 지원, 성능 지표와 임계값처럼 변할 수 있는 사항은 적용 시점의 공식 자료와 실제 구현으로 다시 확인한다.
