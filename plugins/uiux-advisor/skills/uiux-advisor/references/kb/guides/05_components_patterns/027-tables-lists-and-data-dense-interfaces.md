# 테이블·목록·데이터 밀집 인터페이스

## 한 문장 원칙

데이터 관계와 사용자 비교·탐색·행동 과업에 맞춰 테이블과 목록을 선택하고, 밀도·정렬·선택·고정·반응형·접근성을 함께 설계한다.

## 적용 상황

테이블이 레이아웃 용도로 사용되거나 열이 너무 많고 모바일에서 가로 스크롤만 남으며, 정렬·선택·행 행동이 키보드와 보조기술에서 불명확할 때 사용한다.

## 이 가이드가 답하는 결정

1. 이 문제에서 반드시 지켜야 할 사용자 결과와 품질 경계는 무엇인가?
2. 어떤 상태·맥락·사용자 조건을 포함해야 설계가 실제 환경에서 무너지지 않는가?
3. 어떤 증거와 검증 방법으로 이 결정을 승인·수정·폐기할 것인가?

## 핵심 원리

### 관계에 맞는 표현

행과 열을 비교해야 하면 테이블, 개별 항목을 탐색·행동하면 목록·카드를 고려한다.

### 과업 우선 밀도

정보를 많이 보여주는 것보다 사용자가 판단에 필요한 열과 행동을 빠르게 찾는 것이 중요하다.

### 헤더와 상태

열 헤더, 행 헤더, 정렬, 선택, 확장, 편집, 로딩, 빈 상태를 의미적으로 표현한다.

### 반응형 전략

열 숨김만이 아니라 우선 열, 세부 보기, 카드 변환, 가로 스크롤, 고정 열의 장단점을 과업에 맞게 선택한다.

### 대량 작업의 안전

선택 범위, 전체 페이지·전체 결과 차이, 실행 대상 수, 부분 실패를 명확히 한다.

## 규범적 요구사항

> **MUST**는 위반 시 사용자 과업·안전·접근성·신뢰 또는 검증 가능성이 실질적으로 훼손되는 요구사항이다.  
> **SHOULD**는 특별한 맥락과 근거가 있을 때만 예외를 허용하는 강한 권고다.  
> **MAY**는 선택 가능한 구현 방식이며, 대안의 사용자 결과와 위험을 기록해야 한다.

### MUST

- **MUST:** 사용자가 비교·검색·선택·편집·내보내기 중 어떤 과업을 수행하는지 정의하고 표현 패턴을 선택한다.
- **MUST:** 데이터 테이블에는 의미 있는 제목·헤더 관계와 정렬 상태를 제공한다.
- **MUST:** 선택·대량 행동에서 현재 선택 범위와 실제 대상 수, 필터·페이지 영향을 보여준다.
- **MUST:** 로딩·0건·필터 결과 없음·권한 없음·오류·부분 데이터 상태를 구분한다.
- **MUST:** 키보드와 스크린 리더에서 행·열 맥락, 정렬·선택·행 행동을 이해하고 수행할 수 있게 한다.

### SHOULD

- **SHOULD:** 핵심 열을 앞에 두고 드문 상세는 확장·세부 페이지·사용자 열 설정으로 이동한다.
- **SHOULD:** 고정 헤더·열은 맥락을 돕되 확대와 작은 화면에서 콘텐츠를 가리지 않는지 검증한다.
- **SHOULD:** 숫자는 단위·소수점·정렬 기준을 일관되게 하고 텍스트는 잘림 시 전체 값 접근을 제공한다.
- **SHOULD:** 인라인 편집은 저장·취소·검증·동시 수정·키보드 이동을 명확히 한다.

### MAY

- **MAY:** 프로젝트의 플랫폼·도메인·조직 제약이 정당화하면 다른 패턴을 선택할 수 있다. 단, 사용자 결과, 접근성, 위해, 되돌리기 가능성, 검증 계획을 결정 로그에 남긴다.
- **MAY:** 검증 비용을 줄이기 위해 충실도와 방법을 조정할 수 있다. 단, 조정으로 답할 수 없게 된 질문과 미검증 영역을 명시한다.

## 설계·실행 절차

1. 데이터 속성과 사용자 판단·행동 과업, 결과 규모, 업데이트 빈도를 정리한다.
2. 테이블·목록·카드·차트 후보를 비교하고 핵심 정보 우선순위를 정한다.
3. 헤더, 정렬, 필터, 페이지, 선택, 행 행동, 편집, 상태를 명세한다.
4. 반응형, 긴 콘텐츠, 빈 값, 대량 데이터, 권한 차이와 성능을 설계한다.
5. 대표 과업을 키보드·스크린 리더·확대·모바일에서 테스트한다.
6. 열 사용, 정렬·필터 반복, 오선택, 대량 작업 실패를 모니터링한다.

## 예외·극단 상황

- 실시간으로 행이 추가·갱신되는 모니터링 화면
- 가상 스크롤로 DOM에 일부 행만 존재하는 대규모 데이터
- 행마다 권한과 가능한 행동이 다른 관리 도구
- 여러 수준의 그룹 헤더·합계·계층 데이터
- 개인정보 때문에 일부 셀을 마스킹하거나 열람 기록을 남겨야 하는 경우

## 실패 패턴과 교정

| 실패 패턴 | 교정 방법 |
|---|---|
| 화면 정렬을 위해 의미 없는 테이블을 사용한다. | CSS 레이아웃과 의미 구조를 사용하고 실제 표 데이터에만 테이블을 적용한다. |
| 모바일에서 열을 임의로 숨긴다. | 과업 우선 열과 세부 접근, 사용자 선택, 가로 탐색을 명시한다. |
| 체크박스 ‘전체 선택’이 현재 페이지만인지 전체 결과인지 불명확하다. | 범위와 대상 수를 명시하고 전환을 확인하게 한다. |
| 행 전체가 클릭 가능하지만 내부 버튼과 충돌한다. | 주 행동과 보조 행동의 포커스·클릭 영역·키보드 의미를 분리한다. |
| 빈 셀과 0, 알 수 없음, 권한 없음이 같은 표시다. | 데이터 의미별 상태와 설명을 구분한다. |

## 검증 방법

1. 사용자가 핵심 비교·검색·선택 과업을 필요한 열을 찾아 완료하는지 관찰한다.
2. 스크린 리더에서 표 제목, 헤더, 정렬, 행·열 위치, 선택 상태가 전달되는지 확인한다.
3. 확대·작은 화면에서 고정 요소, 가로 스크롤, 행동 접근을 테스트한다.
4. 대량 선택과 부분 실패에서 실제 대상·결과·복구가 정확한지 검증한다.

## 인수 기준

- [ ] 사용자가 비교·검색·선택·편집·내보내기 중 어떤 과업을 수행하는지 정의하고 표현 패턴을 선택한다.
- [ ] 데이터 테이블에는 의미 있는 제목·헤더 관계와 정렬 상태를 제공한다.
- [ ] 선택·대량 행동에서 현재 선택 범위와 실제 대상 수, 필터·페이지 영향을 보여준다.
- [ ] 로딩·0건·필터 결과 없음·권한 없음·오류·부분 데이터 상태를 구분한다.
- [ ] 키보드와 스크린 리더에서 행·열 맥락, 정렬·선택·행 행동을 이해하고 수행할 수 있게 한다.
- [ ] 사용자가 핵심 비교·검색·선택 과업을 필요한 열을 찾아 완료하는지 관찰한다.
- [ ] 스크린 리더에서 표 제목, 헤더, 정렬, 행·열 위치, 선택 상태가 전달되는지 확인한다.
- [ ] 확대·작은 화면에서 고정 요소, 가로 스크롤, 행동 접근을 테스트한다.

## 에이전트 적용 규칙

- 데이터 화면 제안에서 테이블을 자동 선택하지 말고 비교·탐색 과업을 기준으로 판단한다.
- 열 목록뿐 아니라 상태, 선택 범위, 반응형, 접근성, 성능을 포함한다.
- 가상 스크롤의 접근성을 구현 확인 없이 보장하지 않는다.
- 입력에 근거가 없으면 사실을 보충하지 말고 가정, 확인 질문 또는 검증 과제로 표시한다.
- 정적 이미지·텍스트만 제공된 경우 키보드, 포커스, 보조기술, 성능, 동적 상태를 통과했다고 단정하지 않는다.
- 권고를 제시할 때 사용자 영향, 트레이드오프, 검증 방법을 함께 적는다.

- 원문: https://fluent2.microsoft.design/layout

## 범위와 근거 수준

이 문서는 공개 표준, 공공 서비스 가이드, 제품 디자인 시스템, UX 연구 자료를 교차해 재구성한 독립적인 한국어 실무 가이드다. 특정 출처의 원문을 대체하거나 특정 조직의 승인·제휴를 의미하지 않는다.

규범 표준에 직접 근거한 요구사항과 여러 출처를 종합한 실무 권고를 구분해 사용한다. 법률·규제 준수, 현재 제품 기능, 최신 브라우저·보조기술 지원, 성능 지표와 임계값처럼 변할 수 있는 사항은 적용 시점의 공식 자료와 실제 구현으로 다시 확인한다.
