# 대화상자·드로어·오버레이

## 한 문장 원칙

오버레이는 현재 맥락을 잠시 유지하며 집중해야 하는 제한된 작업에만 사용하고, 포커스·배경 상호작용·닫기·히스토리·작업 보존을 명확히 한다.

## 적용 상황

모든 상세·폼·알림을 모달에 넣거나 중첩 모달이 생기고, 닫은 뒤 포커스가 사라지며, 모바일 화면을 가린 상태에서 뒤로 가기가 앱을 종료할 때 사용한다.

## 이 가이드가 답하는 결정

1. 이 문제에서 반드시 지켜야 할 사용자 결과와 품질 경계는 무엇인가?
2. 어떤 상태·맥락·사용자 조건을 포함해야 설계가 실제 환경에서 무너지지 않는가?
3. 어떤 증거와 검증 방법으로 이 결정을 승인·수정·폐기할 것인가?

## 핵심 원리

### 패턴 선택 기준

대화상자는 즉각적인 결정·짧은 작업, 드로어는 보조 맥락·도구, 별도 페이지는 길고 공유·복귀가 필요한 과업에 적합하다.

### 집중과 차단

모달이면 배경을 의미적으로도 상호작용 불가로 만들고 비모달이면 사용자가 배경과 관계를 이해하게 한다.

### 포커스 수명주기

열릴 때 논리적 위치로 이동하고 내부에 유지하며 닫힐 때 호출 요소 또는 다음 합리적 위치로 복원한다.

### 닫기와 손실

Escape, 닫기 버튼, 취소, 외부 클릭, 브라우저 뒤로 가기의 결과와 미저장 데이터 정책을 정의한다.

### 중첩 방지

오버레이 안에서 또 다른 오버레이가 필요한 구조는 과업과 정보구조를 재검토한다.

## 규범적 요구사항

> **MUST**는 위반 시 사용자 과업·안전·접근성·신뢰 또는 검증 가능성이 실질적으로 훼손되는 요구사항이다.  
> **SHOULD**는 특별한 맥락과 근거가 있을 때만 예외를 허용하는 강한 권고다.  
> **MAY**는 선택 가능한 구현 방식이며, 대안의 사용자 결과와 위험을 기록해야 한다.

### MUST

- **MUST:** 오버레이 사용 이유와 별도 페이지·인라인 패턴보다 적합한 근거를 명시한다.
- **MUST:** 제목, 설명, 역할, 초기 포커스, 포커스 트랩, 닫기 후 복귀를 접근 가능하게 구현한다.
- **MUST:** 모달 배경의 키보드·스크린 리더 상호작용을 차단하고 시각적 배경과 의미 상태를 일치시킨다.
- **MUST:** 닫기 수단과 미저장 변경 손실, 파괴적 행동, Escape·뒤로 가기 정책을 정의한다.
- **MUST:** 작은 화면·확대에서 전체 내용과 행동에 스크롤로 접근하고 이중 스크롤을 피한다.

### SHOULD

- **SHOULD:** 초기 포커스는 첫 필드가 아니라 위험·설명·콘텐츠 길이와 과업에 맞는 요소를 선택한다.
- **SHOULD:** 긴 다단계 폼·공유 가능한 상세·독립 URL이 필요한 콘텐츠는 별도 페이지를 우선한다.
- **SHOULD:** 드로어의 모달·비모달 성격과 화면 크기별 전환을 일관되게 정의한다.
- **SHOULD:** 오버레이 열림 상태를 브라우저 히스토리에 넣을지 과업 복귀 요구에 따라 결정한다.

### MAY

- **MAY:** 프로젝트의 플랫폼·도메인·조직 제약이 정당화하면 다른 패턴을 선택할 수 있다. 단, 사용자 결과, 접근성, 위해, 되돌리기 가능성, 검증 계획을 결정 로그에 남긴다.
- **MAY:** 검증 비용을 줄이기 위해 충실도와 방법을 조정할 수 있다. 단, 조정으로 답할 수 없게 된 질문과 미검증 영역을 명시한다.

## 설계·실행 절차

1. 작업 길이, 맥락 유지, 차단 필요, 공유·복귀, 기기 제약으로 패턴을 선택한다.
2. 열기·초기 포커스·내부 탐색·제출·오류·닫기·복귀 상태를 설계한다.
3. 배경 상호작용, 스크롤, Escape, 외부 클릭, 뒤로 가기, 중첩 규칙을 명세한다.
4. 긴 콘텐츠·키보드·보조기술·확대·모바일에서 레이아웃을 검증한다.
5. 미저장 변경과 비동기 처리 중 닫기 시나리오를 테스트한다.
6. 오버레이 이탈, 반복 열기, 뒤로 가기 실패, 포커스 손실을 모니터링한다.

## 예외·극단 상황

- 인증·결제처럼 외부 페이지 또는 브라우저 대화상자가 이어지는 경우
- 오버레이 안의 데이터가 배경 콘텐츠를 실시간 변경하는 경우
- 모바일에서 드로어가 전체 화면 페이지로 변환되는 경우
- 긴 법적 고지나 비교표를 확인해야 행동할 수 있는 경우
- 처리 중 닫아도 백그라운드 작업이 계속되는 경우

## 실패 패턴과 교정

| 실패 패턴 | 교정 방법 |
|---|---|
| 긴 설정 흐름을 모달에 넣는다. | 독립 페이지와 URL, 저장·복귀를 제공하고 모달은 짧은 맥락 작업에 제한한다. |
| 열릴 때 포커스가 배경에 남는다. | 제목·설명 또는 첫 논리적 컨트롤로 이동하고 내부에 유지한다. |
| 닫은 뒤 페이지 상단으로 포커스가 간다. | 호출 요소나 변경된 결과의 합리적 위치로 복원한다. |
| 외부 클릭으로 입력이 즉시 사라진다. | 닫기 정책과 미저장 경고·자동 저장을 과업 위험에 맞게 설계한다. |
| 모달 위에 확인 모달을 중첩한다. | 한 흐름에서 검토·확인 상태를 통합하거나 별도 페이지로 재구성한다. |

## 검증 방법

1. 키보드만으로 열기, 모든 요소 이동, Escape, 제출, 오류, 닫기와 복귀를 테스트한다.
2. 스크린 리더에서 제목·설명·모달 상태가 발표되고 배경이 탐색되지 않는지 확인한다.
3. 200% 이상 확대와 작은 화면에서 콘텐츠·버튼·오류에 접근 가능한지 검증한다.
4. 브라우저 뒤로 가기, 새로고침, 미저장 변경, 처리 중 닫기 결과를 테스트한다.

## 인수 기준

- [ ] 오버레이 사용 이유와 별도 페이지·인라인 패턴보다 적합한 근거를 명시한다.

- [ ] 모달 배경의 키보드·스크린 리더 상호작용을 차단하고 시각적 배경과 의미 상태를 일치시킨다.

- [ ] 키보드만으로 열기, 모든 요소 이동, Escape, 제출, 오류, 닫기와 복귀를 테스트한다.

## 에이전트 적용 규칙

- 모달을 기본 해결책으로 제안하지 말고 인라인·드로어·페이지와 선택 근거를 비교한다.
- 명세에 포커스 수명주기와 배경 상호작용을 반드시 포함한다.
- 외부 클릭 닫기를 안전한 기본값으로 가정하지 않는다.
- 입력에 근거가 없으면 사실을 보충하지 말고 가정, 확인 질문 또는 검증 과제로 표시한다.
- 정적 이미지·텍스트만 제공된 경우 키보드, 포커스, 보조기술, 성능, 동적 상태를 통과했다고 단정하지 않는다.
- 권고를 제시할 때 사용자 영향, 트레이드오프, 검증 방법을 함께 적는다.

### [wai-aria-apg] ARIA Authoring Practices Guide

- 발행·관리 주체: W3C Web Accessibility Initiative
- 유형: implementation-guidance
- 적용 범위: ARIA 위젯 패턴, 키보드 상호작용, 이름·역할·상태 구현

- 원문: https://www.w3.org/WAI/ARIA/apg/

### [w3c-wcag22] Web Content Accessibility Guidelines (WCAG) 2.2

- 발행·관리 주체: W3C
- 유형: standard
- 적용 범위: 웹 콘텐츠 접근성의 시험 가능한 성공 기준과 적합성 수준
- 이 가이드에서의 사용: 접근성 요구사항을 규범적으로 제시할 때 최우선 기준으로 사용한다.
- 원문: https://www.w3.org/TR/WCAG22/

### [fluent-accessibility] Accessibility

- 발행·관리 주체: Fluent 2 Design System
- 유형: product-design-system

- 이 가이드에서의 사용: 멀티플랫폼 제품의 접근성 체크와 구현 협업 기준으로 사용한다.
- 원문: https://fluent2.microsoft.design/accessibility

### [material-states] Interaction States

- 발행·관리 주체: Material Design
- 유형: product-design-system
- 적용 범위: 호버, 포커스, 누름, 드래그, 선택, 비활성 등 상호작용 상태
- 이 가이드에서의 사용: 컴포넌트 상태 모델과 시각적 피드백을 설계할 때 비교 근거로 사용한다.

### [nng-heuristics] 10 Usability Heuristics for User Interface Design

- 발행·관리 주체: Nielsen Norman Group
- 유형: evaluation-framework
- 적용 범위: 시스템 상태, 현실 세계 대응, 통제, 일관성, 오류 방지, 인식, 유연성, 최소성, 복구, 도움말
- 이 가이드에서의 사용: 휴리스틱 리뷰의 관찰 틀로 사용하되 실제 사용자 연구를 대체하지 않는다.
- 원문: https://www.nngroup.com/articles/ten-usability-heuristics/

## 범위와 근거 수준

이 문서는 공개 표준, 공공 서비스 가이드, 제품 디자인 시스템, UX 연구 자료를 교차해 재구성한 독립적인 한국어 실무 가이드다. 특정 출처의 원문을 대체하거나 특정 조직의 승인·제휴를 의미하지 않는다.

규범 표준에 직접 근거한 요구사항과 여러 출처를 종합한 실무 권고를 구분해 사용한다. 법률·규제 준수, 현재 제품 기능, 최신 브라우저·보조기술 지원, 성능 지표와 임계값처럼 변할 수 있는 사항은 적용 시점의 공식 자료와 실제 구현으로 다시 확인한다.
