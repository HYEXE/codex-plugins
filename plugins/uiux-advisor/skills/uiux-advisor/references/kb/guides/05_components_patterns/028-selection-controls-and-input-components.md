# 선택 컨트롤과 입력 컴포넌트

## 한 문장 원칙

선택 수, 옵션 수, 상호배타성, 기본값, 검색 필요성, 결과의 즉시성에 맞춰 라디오·체크박스·스위치·셀렉트·콤보박스를 구분한다.

## 적용 상황

스위치와 체크박스를 의미 없이 바꾸거나, 셀렉트에 너무 많은 옵션을 넣고, 기본 선택이 사용자의 의도를 대신하며, 커스텀 컨트롤이 키보드에서 작동하지 않을 때 사용한다.

## 이 가이드가 답하는 결정

1. 이 문제에서 반드시 지켜야 할 사용자 결과와 품질 경계는 무엇인가?
2. 어떤 상태·맥락·사용자 조건을 포함해야 설계가 실제 환경에서 무너지지 않는가?
3. 어떤 증거와 검증 방법으로 이 결정을 승인·수정·폐기할 것인가?

## 핵심 원리

### 선택 모델

하나 선택, 여러 선택, 즉시 켜기·끄기, 값을 입력해 검색하는 상황은 서로 다른 컨트롤 의미를 가진다.

### 옵션 가시성

옵션이 적고 비교가 중요하면 모두 보이는 라디오·체크박스가, 옵션이 많으면 검색·그룹화가 유리할 수 있다.

### 기본값의 책임

기본 선택은 안전하고 대부분에게 적합하며 사용자가 놓쳐도 위해가 낮을 때만 사용한다.

### 상태와 결과

스위치는 일반적으로 즉시 상태를 바꾸므로 저장 버튼이 필요한 설정과 혼용하면 결과가 불명확해진다.

### 네이티브 우선

네이티브 컨트롤이 제공하는 키보드·이름·상태·모바일 입력을 활용하고 커스텀은 명확한 필요가 있을 때만 만든다.

## 규범적 요구사항

> **MUST**는 위반 시 사용자 과업·안전·접근성·신뢰 또는 검증 가능성이 실질적으로 훼손되는 요구사항이다.  
> **SHOULD**는 특별한 맥락과 근거가 있을 때만 예외를 허용하는 강한 권고다.  
> **MAY**는 선택 가능한 구현 방식이며, 대안의 사용자 결과와 위험을 기록해야 한다.

### MUST

- **MUST:** 컨트롤별 선택 수, 필수 여부, 기본값, 즉시 적용·저장 방식, 취소·복구를 정의한다.
- **MUST:** 레이블과 그룹 제목을 의미적으로 연결하고 각 옵션의 차이와 결과를 이해할 수 있게 한다.
- **MUST:** 키보드·스크린 리더의 표준 조작과 선택·확장·비활성 상태를 구현한다.
- **MUST:** 기본값이 비용·개인정보·위험을 증가시키거나 선택 동의를 대신하지 않게 한다.
- **MUST:** 옵션이 동적으로 변경되면 선택 보존·무효화·알림 규칙을 명확히 한다.

### SHOULD

- **SHOULD:** 적은 옵션은 숨기지 말고 직접 비교 가능하게 노출한다.
- **SHOULD:** 긴 옵션 목록은 검색, 그룹, 최근·추천과 전체 목록 접근을 조합하되 결과를 편향시키지 않는다.
- **SHOULD:** ‘해당 없음’, ‘모름’, ‘기타’가 실제로 의미가 다르면 별도 옵션과 후속 입력을 제공한다.
- **SHOULD:** 비활성 옵션은 이유와 가능한 해결 방법을 제공하거나 목록에서 제외 정책을 일관되게 한다.

### MAY

- **MAY:** 프로젝트의 플랫폼·도메인·조직 제약이 정당화하면 다른 패턴을 선택할 수 있다. 단, 사용자 결과, 접근성, 위해, 되돌리기 가능성, 검증 계획을 결정 로그에 남긴다.
- **MAY:** 검증 비용을 줄이기 위해 충실도와 방법을 조정할 수 있다. 단, 조정으로 답할 수 없게 된 질문과 미검증 영역을 명시한다.

## 설계·실행 절차

1. 선택의 의미, 가능한 값, 선택 수, 빈 값, 기본값, 결과 시점을 정의한다.
2. 라디오·체크박스·스위치·셀렉트·콤보박스 후보를 과업과 옵션 규모로 비교한다.
3. 레이블, 그룹, 설명, 오류, 비활성, 동적 옵션 상태를 설계한다.
4. 키보드·터치·스크린 리더·음성 명령과 모바일 입력을 명세한다.
5. 대표·긴·중복·검색 실패 옵션과 기본값 이해를 테스트한다.
6. 오선택, 변경, 기본값 유지, 검색 실패 데이터를 통해 패턴을 개선한다.

## 예외·극단 상황

- 옵션이 다른 필드 선택에 따라 비동기로 변경되는 경우
- 사용자가 새 옵션을 생성할 수 있는 콤보박스
- 한 옵션이 선택되면 비용·권한·데이터 공개가 즉시 바뀌는 경우
- 조직 정책으로 선택이 잠겨 있지만 현재 상태를 보여줘야 하는 경우
- 수백·수천 개 옵션에 검색·페이지·가상화가 필요한 경우

## 실패 패턴과 교정

| 실패 패턴 | 교정 방법 |
|---|---|
| 저장 버튼이 필요한 설정에 즉시 적용 스위치를 사용한다. | 적용 시점과 가역성에 맞는 체크박스·선택 패턴 또는 자동 저장 피드백을 사용한다. |
| 예/아니오 질문을 모호한 토글 하나로 표시한다. | 명확한 레이블과 현재 상태·변경 결과를 제공한다. |
| 옵션 3개를 셀렉트에 숨긴다. | 직접 비교가 중요하면 라디오로 모두 보이게 한다. |
| 커스텀 드롭다운이 화살표 키와 검색을 지원하지 않는다. | 표준 콤보박스 패턴을 구현하거나 네이티브 컨트롤을 사용한다. |
| 비용이 드는 옵션을 기본 선택한다. | 안전하고 중립적인 기본값 또는 명시적 선택을 사용한다. |

## 검증 방법

1. 사용자가 컨트롤만 보고 선택 수와 적용 시점을 정확히 설명하는지 확인한다.
2. 키보드·스크린 리더로 그룹, 옵션, 선택, 확장, 검색, 오류를 테스트한다.
3. 동적 옵션 변경과 이전 선택 무효화에서 데이터와 알림이 일관되는지 검증한다.
4. 기본값 유지율을 성공으로 보지 않고 이해·의도·변경 후 결과를 조사한다.

## 인수 기준

- [ ] 컨트롤별 선택 수, 필수 여부, 기본값, 즉시 적용·저장 방식, 취소·복구를 정의한다.
- [ ] 레이블과 그룹 제목을 의미적으로 연결하고 각 옵션의 차이와 결과를 이해할 수 있게 한다.
- [ ] 키보드·스크린 리더의 표준 조작과 선택·확장·비활성 상태를 구현한다.
- [ ] 기본값이 비용·개인정보·위험을 증가시키거나 선택 동의를 대신하지 않게 한다.
- [ ] 옵션이 동적으로 변경되면 선택 보존·무효화·알림 규칙을 명확히 한다.
- [ ] 사용자가 컨트롤만 보고 선택 수와 적용 시점을 정확히 설명하는지 확인한다.
- [ ] 키보드·스크린 리더로 그룹, 옵션, 선택, 확장, 검색, 오류를 테스트한다.
- [ ] 동적 옵션 변경과 이전 선택 무효화에서 데이터와 알림이 일관되는지 검증한다.

## 에이전트 적용 규칙

- 컨트롤 추천에는 선택 모델, 옵션 수, 적용 시점, 기본값 위험을 설명한다.
- 커스텀 컴포넌트가 표준 키보드 동작을 자동으로 가진다고 가정하지 않는다.
- 비용·동의·위험 기본값을 임의로 추천하지 않는다.
- 입력에 근거가 없으면 사실을 보충하지 말고 가정, 확인 질문 또는 검증 과제로 표시한다.
- 정적 이미지·텍스트만 제공된 경우 키보드, 포커스, 보조기술, 성능, 동적 상태를 통과했다고 단정하지 않는다.
- 권고를 제시할 때 사용자 영향, 트레이드오프, 검증 방법을 함께 적는다.

## 범위와 근거 수준

이 문서는 공개 표준, 공공 서비스 가이드, 제품 디자인 시스템, UX 연구 자료를 교차해 재구성한 독립적인 한국어 실무 가이드다. 특정 출처의 원문을 대체하거나 특정 조직의 승인·제휴를 의미하지 않는다.

규범 표준에 직접 근거한 요구사항과 여러 출처를 종합한 실무 권고를 구분해 사용한다. 법률·규제 준수, 현재 제품 기능, 최신 브라우저·보조기술 지원, 성능 지표와 임계값처럼 변할 수 있는 사항은 적용 시점의 공식 자료와 실제 구현으로 다시 확인한다.
