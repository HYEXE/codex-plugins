# 콘텐츠 디자인과 평이한 언어

## 한 문장 원칙

사용자가 필요한 정보를 빠르게 찾고 이해하고 행동할 수 있도록 사용자 필요, 정보 순서, 문장, 형식, 유지관리까지 함께 설계한다.

## 적용 상황

화면 문구가 정책·법무·마케팅·개발 용어의 합성물이거나, 사용자가 긴 설명을 읽어도 무엇을 해야 하는지 알기 어렵고, 중복·낡은 콘텐츠가 쌓일 때 사용한다.

## 이 가이드가 답하는 결정

1. 이 문제에서 반드시 지켜야 할 사용자 결과와 품질 경계는 무엇인가?
2. 어떤 상태·맥락·사용자 조건을 포함해야 설계가 실제 환경에서 무너지지 않는가?
3. 어떤 증거와 검증 방법으로 이 결정을 승인·수정·폐기할 것인가?

## 핵심 원리

### 필요에서 시작

콘텐츠 존재 자체가 아니라 어떤 사용자가 어떤 결정을 하거나 과업을 완료하는 데 필요한지 확인한다.

### 앞부분 우선

결론, 필요한 행동, 기한, 자격, 비용 같은 핵심을 앞에 두고 배경과 세부를 뒤에 배치한다.

### 구체적이고 평이한 표현

사용자 언어, 능동형, 짧은 문장, 구체적 동사를 사용하고 불필요한 전문용어와 명사화를 줄인다.

### 구조도 콘텐츠

제목, 소제목, 목록, 표, 링크 문구는 스캔과 의미 구조를 돕도록 설계한다.

### 수명주기

작성자·검토일·정책 근거·중복·폐기 조건을 관리하지 않으면 정확성도 UX도 악화된다.

## 규범적 요구사항

> **MUST**는 위반 시 사용자 과업·안전·접근성·신뢰 또는 검증 가능성이 실질적으로 훼손되는 요구사항이다.  
> **SHOULD**는 특별한 맥락과 근거가 있을 때만 예외를 허용하는 강한 권고다.  
> **MAY**는 선택 가능한 구현 방식이며, 대안의 사용자 결과와 위험을 기록해야 한다.

### MUST

- **MUST:** 각 콘텐츠에 대상 사용자, 사용자 필요, 기대 행동, 정보 소유자, 검토일을 정의한다.
- **MUST:** 제목과 첫 문단만으로 주제, 대상, 필요한 행동 또는 핵심 결론을 이해할 수 있게 한다.
- **MUST:** 중대한 조건·예외·비용·기한을 숨기거나 모호한 링크 뒤로 미루지 않는다.
- **MUST:** 전문용어를 꼭 써야 하면 처음에 평이한 정의와 사용자가 아는 표현을 함께 제공한다.
- **MUST:** 이미지·색상·아이콘에만 핵심 정보를 두지 않고 텍스트로 동등한 정보를 제공한다.

### SHOULD

- **SHOULD:** 한 문단에 하나의 핵심 메시지를 두고 문장·목록·표의 형식을 정보 관계에 맞게 선택한다.
- **SHOULD:** 링크 문구는 문맥 밖에서도 목적을 예측할 수 있게 쓰고 ‘여기’, ‘자세히’만 사용하지 않는다.
- **SHOULD:** 읽기 수준 도구는 신호로만 사용하고 실제 대상 사용자의 이해와 과업 성공으로 검증한다.
- **SHOULD:** 중복 콘텐츠를 통합하고 단일 신뢰 원천과 변경 전파 절차를 운영한다.

### MAY

- **MAY:** 프로젝트의 플랫폼·도메인·조직 제약이 정당화하면 다른 패턴을 선택할 수 있다. 단, 사용자 결과, 접근성, 위해, 되돌리기 가능성, 검증 계획을 결정 로그에 남긴다.
- **MAY:** 검증 비용을 줄이기 위해 충실도와 방법을 조정할 수 있다. 단, 조정으로 답할 수 없게 된 질문과 미검증 영역을 명시한다.

## 설계·실행 절차

1. 사용자 필요와 콘텐츠가 가능하게 할 행동을 한 문장으로 정의한다.
2. 기존 정보에서 필수·보조·중복·낡음·근거 불명 항목을 분류한다.
3. 핵심 결론과 행동을 먼저 둔 구조를 만들고 사용자 언어로 초안을 쓴다.
4. 제목·목록·표·링크·오류·도움말을 의미 구조와 접근성 관점에서 편집한다.
5. 대상 사용자가 정보를 찾고 자신의 말로 설명하고 행동하는지 테스트한다.
6. 소유자, 검토 주기, 변경 의존성, 폐기 조건을 게시 절차에 포함한다.

## 예외·극단 상황

- 법적 정확성과 평이한 표현 사이에 긴장이 있는 약관·고지
- 긴급·재난 상황에서 행동 지침이 매우 짧고 명확해야 하는 경우
- 전문가와 비전문가가 같은 콘텐츠를 사용하는 경우
- 번역 전 원문 구조가 다른 언어의 문법·길이·문화와 맞지 않는 경우
- 개인화로 사람마다 다른 조건·금액·기한이 표시되는 경우

## 실패 패턴과 교정

| 실패 패턴 | 교정 방법 |
|---|---|
| 조직이 말하고 싶은 배경부터 길게 쓴다. | 사용자가 지금 알아야 할 결론과 행동을 먼저 둔다. |
| 평이한 언어를 단순히 짧은 문장으로만 본다. | 용어, 정보 순서, 예시, 구조, 검증을 함께 개선한다. |
| 중요한 조건을 툴팁이나 약관 링크에 숨긴다. | 결정 시점에 핵심 조건을 노출하고 세부 근거로 연결한다. |
| 읽기 점수만 통과하면 이해됐다고 본다. | 대상 사용자의 찾기·이해·행동 과업으로 검증한다. |
| 게시 후 소유자가 없다. | 정확성 책임자, 검토일, 변경 알림, 폐기 기준을 지정한다. |

## 검증 방법

1. 사용자가 필요한 정보를 제한 시간 안에 찾고 자신의 말로 설명하는지 관찰한다.
2. 핵심 조건을 놓친 사용자에게 어떤 제목·순서·용어가 원인이었는지 탐색한다.
3. 스크린 리더 제목 목록과 링크 목록만으로 구조와 목적을 이해할 수 있는지 확인한다.
4. 정책·제품 변경 시 영향을 받는 콘텐츠를 추적하고 검토 기한을 지킨다.

## 인수 기준

- [ ] 각 콘텐츠에 대상 사용자, 사용자 필요, 기대 행동, 정보 소유자, 검토일을 정의한다.
- [ ] 제목과 첫 문단만으로 주제, 대상, 필요한 행동 또는 핵심 결론을 이해할 수 있게 한다.
- [ ] 중대한 조건·예외·비용·기한을 숨기거나 모호한 링크 뒤로 미루지 않는다.
- [ ] 전문용어를 꼭 써야 하면 처음에 평이한 정의와 사용자가 아는 표현을 함께 제공한다.
- [ ] 이미지·색상·아이콘에만 핵심 정보를 두지 않고 텍스트로 동등한 정보를 제공한다.
- [ ] 사용자가 필요한 정보를 제한 시간 안에 찾고 자신의 말로 설명하는지 관찰한다.
- [ ] 핵심 조건을 놓친 사용자에게 어떤 제목·순서·용어가 원인이었는지 탐색한다.
- [ ] 스크린 리더 제목 목록과 링크 목록만으로 구조와 목적을 이해할 수 있는지 확인한다.

## 에이전트 적용 규칙

- 문구를 작성할 때 대상, 행동, 조건, 결과를 먼저 확인하고 마케팅 표현보다 명확성을 우선한다.
- 법적 문구를 임의로 축약해 법적 의미를 바꾸지 말고 전문가 검토 필요성을 표시한다.
- 가독성 수치만으로 품질을 단정하지 않는다.
- 입력에 근거가 없으면 사실을 보충하지 말고 가정, 확인 질문 또는 검증 과제로 표시한다.
- 정적 이미지·텍스트만 제공된 경우 키보드, 포커스, 보조기술, 성능, 동적 상태를 통과했다고 단정하지 않는다.
- 권고를 제시할 때 사용자 영향, 트레이드오프, 검증 방법을 함께 적는다.

## 범위와 근거 수준

이 문서는 공개 표준, 공공 서비스 가이드, 제품 디자인 시스템, UX 연구 자료를 교차해 재구성한 독립적인 한국어 실무 가이드다. 특정 출처의 원문을 대체하거나 특정 조직의 승인·제휴를 의미하지 않는다.

규범 표준에 직접 근거한 요구사항과 여러 출처를 종합한 실무 권고를 구분해 사용한다. 법률·규제 준수, 현재 제품 기능, 최신 브라우저·보조기술 지원, 성능 지표와 임계값처럼 변할 수 있는 사항은 적용 시점의 공식 자료와 실제 구현으로 다시 확인한다.
