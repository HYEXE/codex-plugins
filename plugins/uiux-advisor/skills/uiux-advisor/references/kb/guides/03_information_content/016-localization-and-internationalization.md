# 현지화와 국제화 설계

## 한 문장 원칙

번역을 마지막 문자열 교체로 처리하지 말고 언어, 문화, 방향, 형식, 법·정책, 콘텐츠 길이의 변이를 구조와 컴포넌트 설계에 포함한다.

## 적용 상황

다국어 제품에서 텍스트가 잘리거나 날짜·주소·이름 입력이 특정 국가를 전제하고, 오른쪽에서 왼쪽으로 쓰는 언어와 로케일별 정책이 깨질 때 사용한다.

## 이 가이드가 답하는 결정

1. 이 문제에서 반드시 지켜야 할 사용자 결과와 품질 경계는 무엇인가?
2. 어떤 상태·맥락·사용자 조건을 포함해야 설계가 실제 환경에서 무너지지 않는가?
3. 어떤 증거와 검증 방법으로 이 결정을 승인·수정·폐기할 것인가?

## 핵심 원리

### 언어와 로케일 분리

언어, 지역, 통화, 시간대, 단위, 법적 조건은 서로 다른 설정일 수 있다.

### 콘텐츠 확장성

문자열 길이와 줄바꿈은 언어마다 크게 다르므로 고정 폭·높이와 이미지 속 텍스트를 피한다.

### 의미 있는 구조

문장 조각을 코드에서 조합하면 어순·성·수·격이 다른 언어에서 번역이 불가능해질 수 있다.

### 문화적·제도적 적합성

색상·아이콘·예시·이름·주소·전화·신분 체계는 문화와 제도에 따라 다르다.

### 방향성과 양방향 텍스트

전체 레이아웃 방향과 숫자·코드·이메일 같은 혼합 텍스트 방향을 구분한다.

## 규범적 요구사항

> **MUST**는 위반 시 사용자 과업·안전·접근성·신뢰 또는 검증 가능성이 실질적으로 훼손되는 요구사항이다.  
> **SHOULD**는 특별한 맥락과 근거가 있을 때만 예외를 허용하는 강한 권고다.  
> **MAY**는 선택 가능한 구현 방식이며, 대안의 사용자 결과와 위험을 기록해야 한다.

### MUST

- **MUST:** 페이지와 콘텐츠 조각의 언어를 기계가 식별할 수 있게 하고 언어 전환 결과를 예측 가능하게 한다.
- **MUST:** 날짜, 시간, 숫자, 통화, 단위, 이름, 주소, 전화번호 입력을 단일 국가 형식으로 강제하지 않는다.
- **MUST:** 문장을 재사용 가능한 작은 조각으로 과도하게 분해하거나 변수 순서를 고정하지 않는다.
- **MUST:** 긴 번역, 복수형, 성별 중립 표현, 오른쪽에서 왼쪽 방향, 혼합 텍스트를 테스트한다.
- **MUST:** 번역되지 않은 콘텐츠와 대체 언어 사용을 사용자에게 명확히 알린다.

### SHOULD

- **SHOULD:** 현지 번역가와 콘텐츠 디자이너에게 화면 맥락, 변수 의미, 글자 제한 이유를 제공한다.
- **SHOULD:** 사용자 선택 언어를 존중하되 자동 감지와 강제 리디렉션을 쉽게 변경할 수 있게 한다.
- **SHOULD:** 아이콘·이미지·색상·예시가 문화적으로 오해되거나 배제하지 않는지 검토한다.
- **SHOULD:** 현지화 QA를 스크린샷 비교가 아니라 실제 과업과 입력·오류·검색 흐름까지 수행한다.

### MAY

- **MAY:** 프로젝트의 플랫폼·도메인·조직 제약이 정당화하면 다른 패턴을 선택할 수 있다. 단, 사용자 결과, 접근성, 위해, 되돌리기 가능성, 검증 계획을 결정 로그에 남긴다.
- **MAY:** 검증 비용을 줄이기 위해 충실도와 방법을 조정할 수 있다. 단, 조정으로 답할 수 없게 된 질문과 미검증 영역을 명시한다.

## 설계·실행 절차

1. 지원 로케일과 언어, 정책, 형식, 방향, 콘텐츠 소유권을 정의한다.
2. 하드코딩된 문자열·형식·레이아웃·이미지 텍스트·문장 조합을 인벤토리한다.
3. 컴포넌트를 콘텐츠 확장·줄바꿈·방향 전환에 견디도록 설계한다.
4. 번역 맥락, 용어집, 변수 설명, 검토 절차를 제공한다.
5. 의사 로케일과 대표 실제 언어로 자동·수동 QA를 수행한다.
6. 현지 사용자 과업과 지원 문의로 언어·문화·제도 문제를 지속 개선한다.

## 예외·극단 상황

- 한 화면에 아랍어와 영어 코드·숫자·주소가 섞이는 양방향 텍스트
- 법적 고지와 약관이 국가마다 다른 경우
- 이름·성·호칭·주소가 고정 필드 모델에 맞지 않는 경우
- 번역이 아직 준비되지 않은 신규 기능의 점진 출시
- 사용자가 언어와 지역·통화·시간대를 서로 다르게 설정하려는 경우

## 실패 패턴과 교정

| 실패 패턴 | 교정 방법 |
|---|---|
| 영문 길이에 맞춘 고정 폭 버튼을 사용한다. | 텍스트 확장과 줄바꿈을 허용하고 레이아웃 우선순위를 재설계한다. |
| 날짜를 MM/DD/YYYY 하나로만 입력받는다. | 로케일에 맞는 표시와 명확한 예시·파싱·확인을 제공한다. |
| 단어 조각을 이어 문장을 만든다. | 번역 가능한 완전한 메시지와 위치를 바꿀 수 있는 변수 구조를 사용한다. |
| 브라우저 언어로 강제 이동하고 변경을 숨긴다. | 감지를 제안으로 사용하고 명시적 언어 선택과 지속 설정을 제공한다. |
| 번역만 확인하고 과업은 테스트하지 않는다. | 검색, 입력, 오류, 결제, 문서 출력까지 현지 맥락으로 검증한다. |

## 검증 방법

1. 의사 로케일로 문자열 확장, 악센트, 미번역, 줄바꿈, 방향 문제를 자동 탐지한다.
2. 대표 로케일에서 이름·주소·전화·날짜·통화의 실제 입력과 표시를 테스트한다.
3. 오른쪽에서 왼쪽 언어에서 의미 순서, 아이콘 방향, 포커스 순서, 스크롤을 확인한다.
4. 현지 사용자와 번역가가 문구의 자연스러움뿐 아니라 과업 이해와 정책 적합성을 검토한다.

## 인수 기준

- [ ] 페이지와 콘텐츠 조각의 언어를 기계가 식별할 수 있게 하고 언어 전환 결과를 예측 가능하게 한다.
- [ ] 날짜, 시간, 숫자, 통화, 단위, 이름, 주소, 전화번호 입력을 단일 국가 형식으로 강제하지 않는다.
- [ ] 문장을 재사용 가능한 작은 조각으로 과도하게 분해하거나 변수 순서를 고정하지 않는다.
- [ ] 긴 번역, 복수형, 성별 중립 표현, 오른쪽에서 왼쪽 방향, 혼합 텍스트를 테스트한다.
- [ ] 번역되지 않은 콘텐츠와 대체 언어 사용을 사용자에게 명확히 알린다.
- [ ] 의사 로케일로 문자열 확장, 악센트, 미번역, 줄바꿈, 방향 문제를 자동 탐지한다.

## 에이전트 적용 규칙

- 다국어 명세에는 문자열 길이뿐 아니라 입력 모델, 방향성, 지역 형식, 정책 차이를 포함한다.
- 특정 문화권의 이름·주소 구조를 보편적이라고 가정하지 않는다.
- 자동 번역 품질이나 법적 적합성을 확인되지 않은 상태에서 단정하지 않는다.
- 입력에 근거가 없으면 사실을 보충하지 말고 가정, 확인 질문 또는 검증 과제로 표시한다.
- 정적 이미지·텍스트만 제공된 경우 키보드, 포커스, 보조기술, 성능, 동적 상태를 통과했다고 단정하지 않는다.
- 권고를 제시할 때 사용자 영향, 트레이드오프, 검증 방법을 함께 적는다.

## 범위와 근거 수준

이 문서는 공개 표준, 공공 서비스 가이드, 제품 디자인 시스템, UX 연구 자료를 교차해 재구성한 독립적인 한국어 실무 가이드다. 특정 출처의 원문을 대체하거나 특정 조직의 승인·제휴를 의미하지 않는다.

규범 표준에 직접 근거한 요구사항과 여러 출처를 종합한 실무 권고를 구분해 사용한다. 법률·규제 준수, 현재 제품 기능, 최신 브라우저·보조기술 지원, 성능 지표와 임계값처럼 변할 수 있는 사항은 적용 시점의 공식 자료와 실제 구현으로 다시 확인한다.
