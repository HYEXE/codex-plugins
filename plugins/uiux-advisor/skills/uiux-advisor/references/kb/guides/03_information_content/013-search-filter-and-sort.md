# 검색·필터·정렬

## 한 문장 원칙

사용자가 정확한 용어를 모르거나 결과 집합이 큰 상황을 전제로 검색, 필터, 정렬의 역할과 상태를 분리해 설계한다.

## 적용 상황

검색 결과가 많거나 0건이 자주 발생하고, 필터 적용 상태가 보이지 않거나, 정렬이 사용자의 과업과 무관한 내부 기준으로 제공될 때 사용한다.

## 이 가이드가 답하는 결정

1. 이 문제에서 반드시 지켜야 할 사용자 결과와 품질 경계는 무엇인가?
2. 어떤 상태·맥락·사용자 조건을 포함해야 설계가 실제 환경에서 무너지지 않는가?
3. 어떤 증거와 검증 방법으로 이 결정을 승인·수정·폐기할 것인가?

## 핵심 원리

### 도구별 역할

검색은 질의로 후보를 찾고, 필터는 집합을 제한하며, 정렬은 같은 집합의 순서를 바꾼다. 의미를 섞지 않는다.

### 질의와 상태의 가시성

현재 질의, 적용된 필터, 결과 수, 정렬 기준, 제거 방법을 결과와 함께 보여준다.

### 오류 관용

오탈자, 동의어, 형태 변화, 빈 결과, 부분 일치와 사용자의 문제 중심 언어를 고려한다.

### 결과 설명 가능성

왜 결과가 포함되었고 어떤 범위가 제외되었는지 사용자가 추론할 수 있어야 한다.

### 접근 가능한 조작

필터 패널, 자동완성, 결과 갱신이 키보드·스크린 리더·확대 환경에서 예측 가능해야 한다.

## 규범적 요구사항

> **MUST**는 위반 시 사용자 과업·안전·접근성·신뢰 또는 검증 가능성이 실질적으로 훼손되는 요구사항이다.  
> **SHOULD**는 특별한 맥락과 근거가 있을 때만 예외를 허용하는 강한 권고다.  
> **MAY**는 선택 가능한 구현 방식이며, 대안의 사용자 결과와 위험을 기록해야 한다.

### MUST

- **MUST:** 검색 범위, 기본 정렬, 필터의 포함·제외 의미, 결과 수 계산 기준을 정의한다.
- **MUST:** 적용된 질의·필터·정렬을 결과 영역 가까이 표시하고 개별·전체 해제 경로를 제공한다.
- **MUST:** 0건 상태에서 원인, 철자·범위 제안, 필터 완화, 다른 경로를 제공한다.
- **MUST:** 결과 갱신 시 포커스와 스크롤을 임의로 이동하지 않고 변경 내용을 접근 가능하게 알린다.
- **MUST:** 사용자에게 보이지 않는 개인화·추천·랭킹 요소가 있으면 목적과 주요 영향을 설명한다.

### SHOULD

- **SHOULD:** 검색어 로그, 0건·재검색·필터 반복 행동으로 용어와 색인을 개선한다.
- **SHOULD:** 필터 옵션의 결과 수를 표시하되 성능과 동적 변화가 혼란을 주지 않는지 검증한다.
- **SHOULD:** 모바일에서 적용 전 미리보기와 명시적 적용 방식의 장단점을 과업에 맞게 선택한다.
- **SHOULD:** 필터·정렬 상태를 URL 또는 공유 가능한 상태로 보존한다.

### MAY

- **MAY:** 프로젝트의 플랫폼·도메인·조직 제약이 정당화하면 다른 패턴을 선택할 수 있다. 단, 사용자 결과, 접근성, 위해, 되돌리기 가능성, 검증 계획을 결정 로그에 남긴다.
- **MAY:** 검증 비용을 줄이기 위해 충실도와 방법을 조정할 수 있다. 단, 조정으로 답할 수 없게 된 질문과 미검증 영역을 명시한다.

## 설계·실행 절차

1. 검색이 해결할 과업, 콘텐츠 속성, 사용자 어휘, 결과 규모를 정의한다.
2. 검색·필터·정렬 각각의 책임과 기본 상태를 설계한다.
3. 정상·부분 일치·오탈자·0건·권한 제한·로딩·오류 상태를 명세한다.
4. 자동완성, 최근 검색, 추천 질의의 데이터·개인정보·키보드 동작을 검토한다.
5. 대표 질의와 극단 결과 집합으로 관련성·가독성·조작성을 테스트한다.
6. 운영 데이터로 동의어, 색인, 필터 우선순위와 실패 복구를 개선한다.

## 예외·극단 상황

- 권한에 따라 결과 존재 여부 자체를 노출하면 안 되는 보안 검색
- 가격·인기·관련성 랭킹이 사업 이해관계와 결합된 마켓플레이스
- 검색 결과가 실시간으로 변하거나 매우 큰 데이터 집합
- 여러 언어·표기·단위·고유명사가 섞인 검색
- 필터 조합이 논리적으로 충돌하거나 결과를 반드시 0으로 만드는 경우

## 실패 패턴과 교정

| 실패 패턴 | 교정 방법 |
|---|---|
| 검색과 필터가 적용되었지만 칩이나 요약에 표시하지 않는다. | 현재 결과를 만든 모든 조건을 한곳에서 확인·해제하게 한다. |
| 0건에서 ‘결과 없음’만 보여준다. | 질의 수정, 필터 완화, 대체 범주, 지원 경로를 제공한다. |
| 자동완성 선택이 키보드와 스크린 리더에서 작동하지 않는다. | 표준 콤보박스 상호작용과 활성 옵션·결과 상태를 구현한다. |
| 관련성 기준을 내부 점수로만 둔다. | 사용자 과업과 품질 기준을 정의하고 편향·조작 위험을 검토한다. |
| 필터 변경마다 페이지 상단으로 이동한다. | 조작 위치와 맥락을 유지하고 결과 변경을 비시각적으로 알린다. |

## 검증 방법

1. 실제 검색어로 성공, 재검색, 0건, 오탈자, 동의어 경로를 테스트한다.
2. 필터가 많은 상태에서 적용 조건을 사용자가 정확히 설명하고 제거할 수 있는지 확인한다.
3. 키보드와 스크린 리더로 자동완성, 필터 패널, 결과 갱신을 검증한다.
4. 관련성·정렬 품질을 대표 사용자 과업과 운영 로그로 평가한다.

## 인수 기준

- [ ] 검색 범위, 기본 정렬, 필터의 포함·제외 의미, 결과 수 계산 기준을 정의한다.
- [ ] 적용된 질의·필터·정렬을 결과 영역 가까이 표시하고 개별·전체 해제 경로를 제공한다.
- [ ] 0건 상태에서 원인, 철자·범위 제안, 필터 완화, 다른 경로를 제공한다.
- [ ] 결과 갱신 시 포커스와 스크롤을 임의로 이동하지 않고 변경 내용을 접근 가능하게 알린다.
- [ ] 사용자에게 보이지 않는 개인화·추천·랭킹 요소가 있으면 목적과 주요 영향을 설명한다.
- [ ] 실제 검색어로 성공, 재검색, 0건, 오탈자, 동의어 경로를 테스트한다.
- [ ] 필터가 많은 상태에서 적용 조건을 사용자가 정확히 설명하고 제거할 수 있는지 확인한다.
- [ ] 키보드와 스크린 리더로 자동완성, 필터 패널, 결과 갱신을 검증한다.

## 에이전트 적용 규칙

- 검색 UI 제안에 정상 상태만 제시하지 말고 0건, 부분 일치, 오류, 권한, 갱신 알림을 포함한다.
- 랭킹과 개인화 기준을 객관적 사실처럼 꾸미지 않는다.
- 필터 수보다 정보 속성과 사용자 의사결정에 맞는 그룹을 우선한다.
- 입력에 근거가 없으면 사실을 보충하지 말고 가정, 확인 질문 또는 검증 과제로 표시한다.
- 정적 이미지·텍스트만 제공된 경우 키보드, 포커스, 보조기술, 성능, 동적 상태를 통과했다고 단정하지 않는다.
- 권고를 제시할 때 사용자 영향, 트레이드오프, 검증 방법을 함께 적는다.

## 범위와 근거 수준

이 문서는 공개 표준, 공공 서비스 가이드, 제품 디자인 시스템, UX 연구 자료를 교차해 재구성한 독립적인 한국어 실무 가이드다. 특정 출처의 원문을 대체하거나 특정 조직의 승인·제휴를 의미하지 않는다.

규범 표준에 직접 근거한 요구사항과 여러 출처를 종합한 실무 권고를 구분해 사용한다. 법률·규제 준수, 현재 제품 기능, 최신 브라우저·보조기술 지원, 성능 지표와 임계값처럼 변할 수 있는 사항은 적용 시점의 공식 자료와 실제 구현으로 다시 확인한다.
