# 터치 목표·포인터 대안·확대

## 한 문장 원칙

정밀한 포인터와 작은 화면을 전제하지 말고 충분한 목표 영역, 간격, 드래그 대안, 확대·재배치, 다양한 입력 방식으로 핵심 과업을 수행하게 한다.

## 적용 상황

아이콘이 너무 작거나 인접 행동이 붙어 있고, 드래그만으로 정렬·선택하며, 핀치 줌을 막고, 확대 시 고정 요소가 콘텐츠를 가릴 때 사용한다.

## 이 가이드가 답하는 결정

1. 이 문제에서 반드시 지켜야 할 사용자 결과와 품질 경계는 무엇인가?
2. 어떤 상태·맥락·사용자 조건을 포함해야 설계가 실제 환경에서 무너지지 않는가?
3. 어떤 증거와 검증 방법으로 이 결정을 승인·수정·폐기할 것인가?

## 핵심 원리

### 목표 영역과 간격

보이는 아이콘 크기뿐 아니라 실제 활성 영역과 인접 목표의 오클릭 위험을 고려한다.

### 입력 방식 독립

마우스·터치·스타일러스·키보드·스위치·음성에서 핵심 행동을 달성할 수 있게 한다.

### 드래그 대안

드래그로 가능한 정렬·이동·선택은 클릭·키보드 기반 대안을 제공한다.

### 사용자 확대

핀치·브라우저 확대·텍스트 확대를 막지 않고 콘텐츠가 재배치되고 조작 가능하게 한다.

### 자세와 환경

한 손 사용, 흔들리는 환경, 운동 제약, 장갑, 화면 반사와 피로를 고려한다.

## 규범적 요구사항

> **MUST**는 위반 시 사용자 과업·안전·접근성·신뢰 또는 검증 가능성이 실질적으로 훼손되는 요구사항이다.  
> **SHOULD**는 특별한 맥락과 근거가 있을 때만 예외를 허용하는 강한 권고다.  
> **MAY**는 선택 가능한 구현 방식이며, 대안의 사용자 결과와 위험을 기록해야 한다.

### MUST

- **MUST:** 인터랙티브 목표의 실제 활성 영역과 인접 간격을 접근성 기준과 과업 위험에 맞게 설계한다.
- **MUST:** 드래그·경로 기반 제스처에 단순 포인터·키보드 대안을 제공한다.
- **MUST:** 브라우저·운영체제 확대를 차단하지 않고 확대 후 핵심 콘텐츠와 행동에 접근 가능하게 한다.
- **MUST:** 호버·멀티터치·기기 흔들기 같은 입력을 유일한 방법으로 사용하지 않는다.
- **MUST:** 가상 키보드·안전 영역·고정 요소가 포커스된 입력과 행동을 가리지 않게 한다.

### SHOULD

- **SHOULD:** 빈도 높거나 위험한 행동은 최소 기준보다 더 큰 목표와 충분한 간격을 제공한다.
- **SHOULD:** 아이콘 주변 여백을 시각 크기와 독립적인 클릭 영역으로 활용하되 영역 겹침을 피한다.
- **SHOULD:** 한 손 사용에서 핵심 행동 위치와 위험 행동 분리를 실제 기기로 검증한다.
- **SHOULD:** 사용자 설정의 텍스트·디스플레이 크기 변화와 화면 방향을 지원한다.

### MAY

- **MAY:** 프로젝트의 플랫폼·도메인·조직 제약이 정당화하면 다른 패턴을 선택할 수 있다. 단, 사용자 결과, 접근성, 위해, 되돌리기 가능성, 검증 계획을 결정 로그에 남긴다.
- **MAY:** 검증 비용을 줄이기 위해 충실도와 방법을 조정할 수 있다. 단, 조정으로 답할 수 없게 된 질문과 미검증 영역을 명시한다.

## 설계·실행 절차

1. 모든 포인터·제스처 행동과 실제 목표 영역을 인벤토리한다.
2. 오클릭 위험, 빈도, 가역성, 입력 환경으로 목표 크기와 간격을 정한다.
3. 드래그·호버·멀티포인트 행동의 클릭·키보드 대안을 설계한다.
4. 확대, 재배치, 가상 키보드, 한 손, 방향 전환 상태를 명세한다.
5. 실제 기기와 다양한 운동·시각 조건에서 과업을 테스트한다.
6. 오클릭·취소·확대 사용·제스처 실패 데이터를 개선에 반영한다.

## 예외·극단 상황

- 캔버스·지도·타임라인처럼 드래그와 확대가 핵심인 도구
- 작은 화면에서 여러 행별 아이콘 행동이 밀집된 경우
- 스타일러스 정밀 입력과 손가락 터치를 동시에 지원하는 경우
- 한 손으로 기기를 들고 인증·결제 같은 고위험 행동을 하는 경우
- 브라우저 확대와 앱 내부 캔버스 확대가 충돌하는 경우

## 실패 패턴과 교정

| 실패 패턴 | 교정 방법 |
|---|---|
| 보이는 아이콘만 작고 클릭 영역도 작다. | 활성 영역을 확장하고 인접 목표와 충분히 분리한다. |
| 드래그로만 순서를 바꿀 수 있다. | 이동 버튼, 메뉴, 키보드 조작과 위치 피드백을 제공한다. |
| viewport 설정으로 확대를 막는다. | 사용자 확대를 허용하고 재배치·고정 요소를 개선한다. |
| 호버 시에만 행동이 나타난다. | 포커스·터치·명시적 메뉴에서 발견 가능한 경로를 제공한다. |
| 하단 고정 버튼이 키보드에 가린다. | 뷰포트 변화와 안전 영역에 맞춰 위치를 조정하고 스크롤 접근을 제공한다. |

## 검증 방법

1. 실제 목표 영역을 시각화하고 인접 요소 오클릭을 실제 기기에서 테스트한다.
2. 터치 없이 키보드와 단순 포인터로 모든 드래그·제스처 과업을 수행한다.
3. 핀치·브라우저·텍스트 확대와 가상 키보드에서 콘텐츠·포커스·행동 가시성을 검증한다.
4. 운동 제약, 한 손, 흔들리는 환경과 장갑 사용 시나리오로 과업을 평가한다.

## 인수 기준

- [ ] 인터랙티브 목표의 실제 활성 영역과 인접 간격을 접근성 기준과 과업 위험에 맞게 설계한다.
- [ ] 드래그·경로 기반 제스처에 단순 포인터·키보드 대안을 제공한다.
- [ ] 브라우저·운영체제 확대를 차단하지 않고 확대 후 핵심 콘텐츠와 행동에 접근 가능하게 한다.
- [ ] 호버·멀티터치·기기 흔들기 같은 입력을 유일한 방법으로 사용하지 않는다.
- [ ] 가상 키보드·안전 영역·고정 요소가 포커스된 입력과 행동을 가리지 않게 한다.
- [ ] 실제 목표 영역을 시각화하고 인접 요소 오클릭을 실제 기기에서 테스트한다.
- [ ] 터치 없이 키보드와 단순 포인터로 모든 드래그·제스처 과업을 수행한다.
- [ ] 핀치·브라우저·텍스트 확대와 가상 키보드에서 콘텐츠·포커스·행동 가시성을 검증한다.

## 에이전트 적용 규칙

- 목표 크기는 시각 아이콘 크기와 실제 활성 영역을 구분해 명세한다.
- 특정 픽셀 수를 맥락 없이 보편 기준으로 단정하지 말고 적용 WCAG 기준과 플랫폼 단위를 확인한다.
- 드래그에는 반드시 대체 조작을 제안한다.
- 입력에 근거가 없으면 사실을 보충하지 말고 가정, 확인 질문 또는 검증 과제로 표시한다.
- 정적 이미지·텍스트만 제공된 경우 키보드, 포커스, 보조기술, 성능, 동적 상태를 통과했다고 단정하지 않는다.
- 권고를 제시할 때 사용자 영향, 트레이드오프, 검증 방법을 함께 적는다.

## 근거 출처

### [w3c-wcag22] Web Content Accessibility Guidelines (WCAG) 2.2

- 발행·관리 주체: W3C
- 유형: standard
- 적용 범위: 웹 콘텐츠 접근성의 시험 가능한 성공 기준과 적합성 수준
- 이 가이드에서의 사용: 접근성 요구사항을 규범적으로 제시할 때 최우선 기준으로 사용한다.
- 원문: https://www.w3.org/TR/WCAG22/

### [fluent-accessibility] Accessibility

- 발행·관리 주체: Fluent 2 Design System
- 유형: product-design-system
- 적용 범위: 포용적 설계, 키보드, 스크린 리더, 색상, 확대와 입력 방식
- 이 가이드에서의 사용: 멀티플랫폼 제품의 접근성 체크와 구현 협업 기준으로 사용한다.
- 원문: https://fluent2.microsoft.design/accessibility

### [material-usability] Usability

- 발행·관리 주체: Material Design
- 유형: product-design-system
- 적용 범위: 이해 가능성, 유용성, 효율성, 접근성의 기본 설계 관점
- 이 가이드에서의 사용: 제품 패턴을 일반 사용성 기준과 대조할 때 보조 자료로 사용한다.
- 원문: https://m3.material.io/foundations/usability

### [wai-aria-apg] ARIA Authoring Practices Guide

- 발행·관리 주체: W3C Web Accessibility Initiative
- 유형: implementation-guidance
- 적용 범위: ARIA 위젯 패턴, 키보드 상호작용, 이름·역할·상태 구현
- 이 가이드에서의 사용: 네이티브 HTML로 해결할 수 없는 복합 위젯의 상호작용 모델을 설계할 때 사용한다.
- 원문: https://www.w3.org/WAI/ARIA/apg/

### [spectrum-inclusive] Inclusive Design

- 발행·관리 주체: Spectrum Design System
- 유형: product-design-system
- 적용 범위: 다양한 능력, 상황, 문화권을 고려한 포용적 설계
- 이 가이드에서의 사용: 평균 사용자 가정을 깨고 배제 위험을 발견할 때 사용한다.
- 원문: https://spectrum.adobe.com/page/inclusive-design/

## 범위와 근거 수준

이 문서는 공개 표준, 공공 서비스 가이드, 제품 디자인 시스템, UX 연구 자료를 교차해 재구성한 독립적인 한국어 실무 가이드다. 특정 출처의 원문을 대체하거나 특정 조직의 승인·제휴를 의미하지 않는다.

규범 표준에 직접 근거한 요구사항과 여러 출처를 종합한 실무 권고를 구분해 사용한다. 법률·규제 준수, 현재 제품 기능, 최신 브라우저·보조기술 지원, 성능 지표와 임계값처럼 변할 수 있는 사항은 적용 시점의 공식 자료와 실제 구현으로 다시 확인한다.
