# 인지 접근성과 복잡성 완화

## 한 문장 원칙

기억·주의·언어·계획·시간 압박의 부담을 줄이고 정보를 외부화하며 사용자가 실수해도 맥락을 잃지 않고 회복하게 한다.

## 적용 상황

긴 지침을 기억해야 하거나 시간 제한, 복잡한 다단계 선택, 불일치한 용어, 과도한 알림, 인증 퍼즐이 과업을 어렵게 할 때 사용한다.

## 이 가이드가 답하는 결정

1. 이 문제에서 반드시 지켜야 할 사용자 결과와 품질 경계는 무엇인가?
2. 어떤 상태·맥락·사용자 조건을 포함해야 설계가 실제 환경에서 무너지지 않는가?
3. 어떤 증거와 검증 방법으로 이 결정을 승인·수정·폐기할 것인가?

## 핵심 원리

### 인식이 회상보다 우선

사용자가 기억해 입력하기보다 현재 가능한 선택, 이전 답, 예시, 진행 상태를 볼 수 있게 한다.

### 한 번에 필요한 정보

복잡한 과업을 의미 있는 단계로 나누고 현재 결정에 필요한 정보와 행동을 가까이 둔다.

### 일관성과 예측

용어·위치·상호작용·오류·도움 경로가 반복되면 학습 부담이 줄어든다.

### 시간과 압박 제어

시간 제한·자동 로그아웃·움직이는 콘텐츠·긴급 문구를 최소화하고 연장·일시정지·저장을 제공한다.

### 실수 친화성

복구, 검토, 실행 취소, 데이터 보존과 평이한 오류로 실패가 과업 포기로 이어지지 않게 한다.

## 규범적 요구사항

> **MUST**는 위반 시 사용자 과업·안전·접근성·신뢰 또는 검증 가능성이 실질적으로 훼손되는 요구사항이다.  
> **SHOULD**는 특별한 맥락과 근거가 있을 때만 예외를 허용하는 강한 권고다.  
> **MAY**는 선택 가능한 구현 방식이며, 대안의 사용자 결과와 위험을 기록해야 한다.

### MUST

- **MUST:** 핵심 지침·조건·상태를 사용자가 기억에만 의존하지 않도록 과업 위치에 지속 제공한다.
- **MUST:** 시간 제한이 있으면 사전 경고, 연장·해제 가능성, 데이터 보존과 예외를 제공한다.
- **MUST:** 불필요한 인증·재입력·문맥 전환을 줄이고 이미 제공한 정보를 다시 요구하지 않는다.
- **MUST:** 평이하고 일관된 용어와 구체적 오류·복구 안내를 사용한다.
- **MUST:** 자동 재생·팝업·알림·시각적 혼잡이 주의를 강제로 전환하지 않게 통제한다.

### SHOULD

- **SHOULD:** 긴 과업에 진행 상태, 저장, 요약, 검토, 변경 경로를 제공한다.
- **SHOULD:** 선택지를 의미 있는 그룹으로 줄이고 비교 기준을 명시한다.
- **SHOULD:** 복잡한 설명은 예시·그림·단계별 도움을 제공하되 텍스트 정보를 대체하지 않는다.
- **SHOULD:** 비밀번호 관리자, 붙여넣기, 접근 가능한 인증 대안과 사용자 지원을 제공한다.

### MAY

- **MAY:** 프로젝트의 플랫폼·도메인·조직 제약이 정당화하면 다른 패턴을 선택할 수 있다. 단, 사용자 결과, 접근성, 위해, 되돌리기 가능성, 검증 계획을 결정 로그에 남긴다.
- **MAY:** 검증 비용을 줄이기 위해 충실도와 방법을 조정할 수 있다. 단, 조정으로 답할 수 없게 된 질문과 미검증 영역을 명시한다.

## 설계·실행 절차

1. 과업에서 사용자가 기억·주의·계획·언어·시간을 써야 하는 지점을 표시한다.
2. 정보를 외부화하고 단계·선택·도움·검토·저장 구조를 재설계한다.
3. 시간 제한, 알림, 인증, 재입력, 오류의 부담과 대안을 정의한다.
4. 평이한 콘텐츠와 일관된 패턴을 적용하고 감정적 압박을 제거한다.
5. 인지·언어·주의 다양성이 있는 사용자와 실제 과업을 테스트한다.
6. 중단·재시도·지원·오류·완료 시간으로 복잡성을 지속 줄인다.

## 예외·극단 상황

- 보안·시험·예약처럼 실제 시간 제한이 필요한 경우
- 의료·재정·법률처럼 많은 조건을 반드시 이해해야 하는 고위험 결정
- 여러 단계에서 다른 사람의 정보·승인·문서를 준비해야 하는 과업
- 인지 부담이 큰 긴급·스트레스 상황
- 숙련 사용자의 고밀도·단축키 요구와 초보 사용자의 명확성 요구가 공존하는 경우

## 실패 패턴과 교정

| 실패 패턴 | 교정 방법 |
|---|---|
| 보안 때문에 붙여넣기와 비밀번호 관리자를 막는다. | 실제 위협 모델을 검토하고 접근 가능한 인증·관리자 사용을 허용한다. |
| 긴 지침을 첫 화면에 한 번만 보여준다. | 관련 단계와 필드 가까이에 핵심 조건을 반복 제공한다. |
| 시간 제한이 예고 없이 만료된다. | 남은 시간, 경고, 연장, 저장·복귀 정책을 제공한다. |
| 오류를 사용자의 주의 부족으로 표현한다. | 문제와 해결 방법을 구체적으로 설명하고 작업을 보존한다. |
| 모든 옵션과 고급 설정을 한 번에 노출한다. | 핵심 과업과 고급 선택을 계층화하고 상태를 잃지 않게 한다. |

## 검증 방법

1. 사용자가 지침을 다시 찾고 중단 후 같은 위치에서 과업을 이어가는지 관찰한다.
2. 시간 제한·세션 만료·오류·인증 실패에서 데이터 보존과 복구를 테스트한다.
3. 인지·언어·주의 다양성이 있는 참가자와 이해·오류·도움 요구를 평가한다.
4. 지원 문의와 반복 오류를 개인 실수로 분류하지 않고 구조적 복잡성으로 분석한다.

## 인수 기준

- [ ] 핵심 지침·조건·상태를 사용자가 기억에만 의존하지 않도록 과업 위치에 지속 제공한다.
- [ ] 시간 제한이 있으면 사전 경고, 연장·해제 가능성, 데이터 보존과 예외를 제공한다.
- [ ] 불필요한 인증·재입력·문맥 전환을 줄이고 이미 제공한 정보를 다시 요구하지 않는다.
- [ ] 평이하고 일관된 용어와 구체적 오류·복구 안내를 사용한다.
- [ ] 자동 재생·팝업·알림·시각적 혼잡이 주의를 강제로 전환하지 않게 통제한다.
- [ ] 사용자가 지침을 다시 찾고 중단 후 같은 위치에서 과업을 이어가는지 관찰한다.
- [ ] 시간 제한·세션 만료·오류·인증 실패에서 데이터 보존과 복구를 테스트한다.
- [ ] 인지·언어·주의 다양성이 있는 참가자와 이해·오류·도움 요구를 평가한다.

## 에이전트 적용 규칙

- 복잡한 과업을 단순히 단계 수로 줄이지 말고 기억·주의·재입력·시간 부담을 분석한다.
- 의료적 진단이나 특정 장애 특성을 임의로 추정하지 않는다.
- 숙련 사용자 효율과 초보 사용자 지원을 설정·점진 공개로 조정한다.
- 입력에 근거가 없으면 사실을 보충하지 말고 가정, 확인 질문 또는 검증 과제로 표시한다.
- 정적 이미지·텍스트만 제공된 경우 키보드, 포커스, 보조기술, 성능, 동적 상태를 통과했다고 단정하지 않는다.
- 권고를 제시할 때 사용자 영향, 트레이드오프, 검증 방법을 함께 적는다.

### [w3c-wcag22] Web Content Accessibility Guidelines (WCAG) 2.2

- 발행·관리 주체: W3C
- 유형: standard

- 원문: https://www.w3.org/TR/WCAG22/

### [wai-accessibility-intro] Introduction to Web Accessibility

- 발행·관리 주체: W3C Web Accessibility Initiative
- 유형: foundational-guidance
- 적용 범위: 장애, 상황적 제약, 포용성, 조직적 접근성의 기본 개념
- 이 가이드에서의 사용: 접근성을 특정 사용자군의 예외가 아니라 제품 품질로 설명할 때 사용한다.
- 원문: https://www.w3.org/WAI/fundamentals/accessibility-intro/

### [spectrum-inclusive] Inclusive Design

- 발행·관리 주체: Spectrum Design System

- 원문: https://spectrum.adobe.com/page/inclusive-design/

### [plainlanguage-gov] Plain Language Guide Series

- 발행·관리 주체: Digital.gov

- 적용 범위: 독자가 이해하고 행동할 수 있는 명확한 공공 콘텐츠 작성
- 이 가이드에서의 사용: 문장, 구조, 용어와 검증 기준을 독자 중심으로 설계할 때 사용한다.
- 원문: https://www.plainlanguage.gov/

### [govuk-question-pages] Question Pages Pattern

- 발행·관리 주체: GOV.UK Design System
- 유형: interaction-pattern
- 적용 범위: 질문 단위 페이지, 레이블·범례·제목 관계와 집중도
- 이 가이드에서의 사용: 복잡한 입력 과정을 단계화하고 질문을 명확하게 만들 때 사용한다.
- 원문: https://design-system.service.gov.uk/patterns/question-pages/

## 범위와 근거 수준

이 문서는 공개 표준, 공공 서비스 가이드, 제품 디자인 시스템, UX 연구 자료를 교차해 재구성한 독립적인 한국어 실무 가이드다. 특정 출처의 원문을 대체하거나 특정 조직의 승인·제휴를 의미하지 않는다.

규범 표준에 직접 근거한 요구사항과 여러 출처를 종합한 실무 권고를 구분해 사용한다. 법률·규제 준수, 현재 제품 기능, 최신 브라우저·보조기술 지원, 성능 지표와 임계값처럼 변할 수 있는 사항은 적용 시점의 공식 자료와 실제 구현으로 다시 확인한다.
