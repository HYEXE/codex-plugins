# 실험과 근거 품질

## 한 문장 원칙

실험은 단기 지표를 최대화하는 장치가 아니라 명시한 가설을 반증 가능하게 검증하고 사용자 위해와 장기 효과를 함께 판단하는 과정이다.

## 적용 상황

A/B 테스트 결과가 자동으로 올바른 디자인을 결정한다고 보거나, 여러 지표·세그먼트를 사후 탐색해 유리한 결과만 채택하거나, 실험이 신뢰·이해·접근성에 미친 영향을 측정하지 않을 때 사용한다.

## 이 가이드가 답하는 결정

1. 이 문제에서 반드시 지켜야 할 사용자 결과와 품질 경계는 무엇인가?
2. 어떤 상태·맥락·사용자 조건을 포함해야 설계가 실제 환경에서 무너지지 않는가?
3. 어떤 증거와 검증 방법으로 이 결정을 승인·수정·폐기할 것인가?

## 핵심 원리

### 사전 명세

가설, 주요 지표, 방어 지표, 분석 대상, 기간, 중단 기준을 결과를 보기 전에 정해야 선택적 해석을 줄일 수 있다.

### 인과 범위

실험은 지정된 모집단·환경·기간의 변화 효과를 추정한다. 왜 그런 효과가 났는지와 장기 일반화는 추가 근거가 필요하다.

### 윤리적 경계

사용자를 속이거나 중대한 정보를 숨기거나 취약 집단에 불균형한 위험을 주는 변형은 지표 성과와 무관하게 허용하지 않는다.

### 다중 근거

정량 결과를 사용성·인터뷰·지원·접근성·성능 데이터와 결합해 메커니즘과 부작용을 이해한다.

### 학습 보존

승자 화면만 남기지 않고 가설, 실행 조건, 결과, 한계, 후속 질문을 저장해 같은 실험을 반복하지 않는다.

## 규범적 요구사항

> **MUST**는 위반 시 사용자 과업·안전·접근성·신뢰 또는 검증 가능성이 실질적으로 훼손되는 요구사항이다.  
> **SHOULD**는 특별한 맥락과 근거가 있을 때만 예외를 허용하는 강한 권고다.  
> **MAY**는 선택 가능한 구현 방식이며, 대안의 사용자 결과와 위험을 기록해야 한다.

### MUST

- **MUST:** 실험 전에 사용자·문제·변경 메커니즘·예상 결과를 연결한 가설을 기록한다.
- **MUST:** 주요 지표, 방어 지표, 대상 사용자, 제외 조건, 분석 기간, 중단·롤백 기준을 사전 정의한다.
- **MUST:** 동의·가격·해지·개인정보·안전처럼 중대한 선택을 기만적으로 조작하는 변형을 실험하지 않는다.
- **MUST:** 접근성·성능·오류·지원 부담·사용자군 격차가 악화되는지 확인하고 심각한 위해 신호가 나오면 즉시 중단한다.
- **MUST:** 통계 결과를 확정적 진실로 표현하지 않고 효과 크기, 불확실성, 데이터 품질, 일반화 한계를 함께 보고한다.

### SHOULD

- **SHOULD:** 실험 전후에 정성 연구를 사용해 변화가 작동한 이유와 실패 경로를 설명한다.
- **SHOULD:** 동시에 여러 지표와 세그먼트를 탐색하면 탐색적 분석으로 표시하고 후속 검증을 분리한다.
- **SHOULD:** 신규성 효과와 장기 습관 변화가 예상되면 충분한 관찰 기간과 사후 모니터링을 둔다.
- **SHOULD:** 실험 대상에서 배제된 사용자와 환경을 기록하고 별도 검증 계획을 만든다.

### MAY

- **MAY:** 프로젝트의 플랫폼·도메인·조직 제약이 정당화하면 다른 패턴을 선택할 수 있다. 단, 사용자 결과, 접근성, 위해, 되돌리기 가능성, 검증 계획을 결정 로그에 남긴다.
- **MAY:** 검증 비용을 줄이기 위해 충실도와 방법을 조정할 수 있다. 단, 조정으로 답할 수 없게 된 질문과 미검증 영역을 명시한다.

## 설계·실행 절차

1. 의사결정과 위험한 가정을 정의하고 실험이 적절한 방법인지 판단한다.
2. 가설·변형·주요·방어 지표·분석 계획·윤리 경계를 사전 등록한다.
3. 계측과 무작위 배정, 노출, 오염, 표본 누락을 파일럿으로 검증한다.
4. 실험 중 위해·품질 경보를 모니터링하고 사전 기준에 따라 중단한다.
5. 결과를 효과 크기·불확실성·세그먼트·부작용·정성 증거와 함께 해석한다.
6. 출시·재실험·기각·추가 연구 결정을 기록하고 장기 결과를 추적한다.

## 예외·극단 상황

- 네트워크 효과나 협업 기능 때문에 사용자 간 변형이 서로 영향을 주는 제품
- 저빈도·고위험 사건으로 표본 확보가 어렵고 실험 자체가 비윤리적인 도메인
- 계절·캠페인·정책 변경이 실험 기간과 동시에 일어나는 상황
- 알고리즘·AI 모델이 실험 중 갱신되어 변형이 고정되지 않는 기능
- 접근성 사용자군처럼 수가 적어 평균 효과에 묻히지만 실패 비용이 큰 집단

## 실패 패턴과 교정

| 실패 패턴 | 교정 방법 |
|---|---|
| 유의한 지표가 나올 때까지 여러 분석을 반복한다. | 주요 분석을 사전 고정하고 사후 탐색은 별도 가설로 재검증한다. |
| 전환이 올랐으니 사용자에게 좋다고 결론낸다. | 이해, 취소·환불, 신뢰, 오류, 접근성 방어 지표를 함께 본다. |
| 승자 변형을 모든 사용자에게 즉시 일반화한다. | 대상 범위와 누락 집단을 기록하고 점진 배포와 사후 모니터링을 한다. |
| 실험이 불가능한 문제도 A/B 테스트로 해결하려 한다. | 탐색 연구, 사용성 테스트, 시뮬레이션, 로그 분석 등 질문에 맞는 방법을 선택한다. |
| 실패한 실험 기록을 삭제한다. | 기각된 가설과 조건을 보존해 반복 비용과 선택 편향을 줄인다. |

## 검증 방법

1. 사전 명세와 최종 보고서를 비교해 지표·표본·기간·분석 변경을 모두 설명했는지 확인한다.
2. 계측 로그에서 노출, 배정, 중복, 누락, 교차 오염을 점검한다.
3. 정성 증거와 지원·오류 데이터를 통해 수치 변화의 메커니즘을 검토한다.
4. 출시 후 장기 지표와 사용자군 격차가 유지되는지 사후 검증한다.

## 인수 기준

- [ ] 실험 전에 사용자·문제·변경 메커니즘·예상 결과를 연결한 가설을 기록한다.
- [ ] 주요 지표, 방어 지표, 대상 사용자, 제외 조건, 분석 기간, 중단·롤백 기준을 사전 정의한다.

- [ ] 접근성·성능·오류·지원 부담·사용자군 격차가 악화되는지 확인하고 심각한 위해 신호가 나오면 즉시 중단한다.

## 에이전트 적용 규칙

- 실험안을 만들 때 가설, 사전 분석, 방어 지표, 윤리 경계, 롤백 기준을 필수로 포함한다.
- 구체적 통계 방법이나 임계값은 데이터 구조와 조직 표준을 확인하지 않고 임의로 확정하지 않는다.
- 단기 전환 개선을 사용자 가치와 동일시하지 않는다.
- 입력에 근거가 없으면 사실을 보충하지 말고 가정, 확인 질문 또는 검증 과제로 표시한다.
- 정적 이미지·텍스트만 제공된 경우 키보드, 포커스, 보조기술, 성능, 동적 상태를 통과했다고 단정하지 않는다.
- 권고를 제시할 때 사용자 영향, 트레이드오프, 검증 방법을 함께 적는다.

## 범위와 근거 수준

이 문서는 공개 표준, 공공 서비스 가이드, 제품 디자인 시스템, UX 연구 자료를 교차해 재구성한 독립적인 한국어 실무 가이드다. 특정 출처의 원문을 대체하거나 특정 조직의 승인·제휴를 의미하지 않는다.

규범 표준에 직접 근거한 요구사항과 여러 출처를 종합한 실무 권고를 구분해 사용한다. 법률·규제 준수, 현재 제품 기능, 최신 브라우저·보조기술 지원, 성능 지표와 임계값처럼 변할 수 있는 사항은 적용 시점의 공식 자료와 실제 구현으로 다시 확인한다.

> **최신성 주의:** 이 가이드는 시간에 따라 정의·도구·권고가 바뀔 수 있는 내용을 포함한다. 현재 공식 문서와 운영 데이터를 확인하지 않은 수치·기능·임계값은 미검증으로 표시한다.
