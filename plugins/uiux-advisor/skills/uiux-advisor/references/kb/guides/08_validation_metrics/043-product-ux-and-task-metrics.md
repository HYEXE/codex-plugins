# 제품 UX 지표와 과업 지표

## 한 문장 원칙

UX 지표는 제품 참여량을 대신하는 단일 점수가 아니라 사용자 결과, 과업 품질, 경험 신호, 위해, 기술 품질을 연결한 측정 체계로 설계한다.

## 적용 상황

페이지뷰·체류시간·전환율만으로 경험 품질을 판단하거나, 만족도 점수는 있지만 어떤 과업과 설계 결정이 영향을 주는지 알 수 없을 때 사용한다.

## 이 가이드가 답하는 결정

1. 이 문제에서 반드시 지켜야 할 사용자 결과와 품질 경계는 무엇인가?
2. 어떤 상태·맥락·사용자 조건을 포함해야 설계가 실제 환경에서 무너지지 않는가?
3. 어떤 증거와 검증 방법으로 이 결정을 승인·수정·폐기할 것인가?

## 핵심 원리

### 결과 계층

사업 결과, 사용자 결과, 과업 성과, 인식·신뢰, 기술 품질을 구분하고 인과 가설로 연결한다.

### 행동과 품질

완료율만 보면 잘못된 완료, 재작업, 환불, 지원 요청, 오류 복구 비용이 숨는다.

### 세분화와 형평성

평균값은 장애, 언어, 기기, 연결 상태, 신규·숙련 사용자 간 격차를 숨길 수 있다.

### 대리 지표의 한계

클릭·체류·재방문은 가치와 피해를 동시에 반영할 수 있다. 지표가 최적화될 때 생길 역효과를 정의한다.

### 계측 품질

이벤트 이름, 시작·종료 조건, 누락, 중복, 개인정보, 버전 변경을 관리하지 않으면 수치가 정밀해 보여도 근거가 약하다.

## 규범적 요구사항

> **MUST**는 위반 시 사용자 과업·안전·접근성·신뢰 또는 검증 가능성이 실질적으로 훼손되는 요구사항이다.  
> **SHOULD**는 특별한 맥락과 근거가 있을 때만 예외를 허용하는 강한 권고다.  
> **MAY**는 선택 가능한 구현 방식이며, 대안의 사용자 결과와 위험을 기록해야 한다.

### MUST

- **MUST:** 각 지표에 사용자 결과 가설, 계산 정의, 대상 모집단, 세분화 기준, 데이터 출처, 책임자, 검토 주기를 기록한다.
- **MUST:** 핵심 과업은 완료 여부와 함께 오류, 재시도, 중단, 복구, 도움 요청, 완료 품질을 측정한다.
- **MUST:** 주요 성공 지표마다 사용자 위해·불공정·신뢰 저하를 탐지하는 방어 지표를 둔다.
- **MUST:** 성능 지표는 현재 권고 정의와 실제 사용자 필드 데이터를 확인하고 버전·측정 환경을 기록한다.
- **MUST:** 개인정보 최소화와 목적 제한을 적용하고 민감한 세분화가 재식별·차별 위험을 만드는지 검토한다.

### SHOULD

- **SHOULD:** 정량 지표를 인터뷰·사용성 테스트·지원 문의·접근성 검증과 함께 해석한다.
- **SHOULD:** 평균뿐 아니라 분포, 상위 지연, 실패 경로, 장치·네트워크·사용자군 차이를 본다.
- **SHOULD:** 지표 변경이나 계측 리팩터링 시 전후 비교 가능성과 데이터 단절을 기록한다.
- **SHOULD:** 팀이 실제로 행동을 바꿀 수 없는 허영 지표는 대시보드에서 제거하거나 참고 수준으로 낮춘다.

### MAY

- **MAY:** 프로젝트의 플랫폼·도메인·조직 제약이 정당화하면 다른 패턴을 선택할 수 있다. 단, 사용자 결과, 접근성, 위해, 되돌리기 가능성, 검증 계획을 결정 로그에 남긴다.
- **MAY:** 검증 비용을 줄이기 위해 충실도와 방법을 조정할 수 있다. 단, 조정으로 답할 수 없게 된 질문과 미검증 영역을 명시한다.

## 설계·실행 절차

1. 사용자 결과와 실패 비용을 정의하고 제품 목표와 구분한다.
2. 결과를 선행 행동, 과업 성과, 인식, 기술 품질, 위해 지표로 분해한다.
3. 이벤트·설문·연구 데이터의 수집 정의와 품질 검사를 설계한다.
4. 기준선과 세분화 격차를 확인하고 목표·경보·반증 기준을 정한다.
5. 정기 리뷰에서 변화의 원인을 여러 근거로 검증하고 인과를 과장하지 않는다.
6. 지표가 유도한 부작용을 모니터링하고 측정 체계를 갱신한다.

## 예외·극단 상황

- 저빈도지만 실패 비용이 커서 통계적 신호가 늦게 나타나는 과업
- 개인정보 때문에 세밀한 세분화와 경로 추적이 제한되는 서비스
- 오프라인·콜센터·제3자 채널에서 과업이 이어져 제품 이벤트만으로 완료를 알 수 없는 흐름
- 장기 학습·건강·재정 결과가 단기 참여 지표와 반대 방향으로 움직이는 제품
- 자동화·AI가 사용자 대신 과업을 수행해 클릭 감소가 오히려 성공일 수 있는 경험

## 실패 패턴과 교정

| 실패 패턴 | 교정 방법 |
|---|---|
| 체류시간 증가를 무조건 성공으로 본다. | 사용자가 더 빠르게 목적을 달성해야 하는 과업인지 확인하고 완료 품질·재작업을 함께 본다. |
| 평균 완료율만 보고 취약 사용자의 실패를 놓친다. | 의미 있는 조건별 분포와 격차를 분석하되 개인정보 위험을 관리한다. |
| 설문 점수 변화를 특정 UI 변경의 효과로 단정한다. | 동시 변화와 표본 편향을 검토하고 실험·정성 근거로 보강한다. |
| 이벤트 이름은 같지만 의미가 릴리스마다 달라진다. | 계측 스키마와 버전을 관리하고 정의 변경 시 데이터 단절을 명시한다. |
| 성공 지표만 최적화해 취소·지원·신뢰 문제가 증가한다. | 방어 지표와 중단 기준을 같은 의사결정 권한으로 운영한다. |

## 검증 방법

1. 지표 정의만 보고 서로 다른 분석가가 같은 데이터를 계산하는지 재현성을 확인한다.
2. 계측 이벤트를 실제 사용자 경로와 대조해 누락·중복·잘못된 시작·종료를 점검한다.
3. 지표 변화가 사용자 행동 영상·연구·지원 데이터와 일치하는지 삼각 검증한다.
4. 지표를 최적화한 팀이 사용자에게 해로운 행동을 선택할 유인이 있는지 역설계 검토한다.

## 인수 기준

- [ ] 각 지표에 사용자 결과 가설, 계산 정의, 대상 모집단, 세분화 기준, 데이터 출처, 책임자, 검토 주기를 기록한다.
- [ ] 핵심 과업은 완료 여부와 함께 오류, 재시도, 중단, 복구, 도움 요청, 완료 품질을 측정한다.
- [ ] 주요 성공 지표마다 사용자 위해·불공정·신뢰 저하를 탐지하는 방어 지표를 둔다.
- [ ] 성능 지표는 현재 권고 정의와 실제 사용자 필드 데이터를 확인하고 버전·측정 환경을 기록한다.
- [ ] 개인정보 최소화와 목적 제한을 적용하고 민감한 세분화가 재식별·차별 위험을 만드는지 검토한다.
- [ ] 지표 정의만 보고 서로 다른 분석가가 같은 데이터를 계산하는지 재현성을 확인한다.
- [ ] 계측 이벤트를 실제 사용자 경로와 대조해 누락·중복·잘못된 시작·종료를 점검한다.
- [ ] 지표 변화가 사용자 행동 영상·연구·지원 데이터와 일치하는지 삼각 검증한다.

## 에이전트 적용 규칙

- 지표를 제안할 때 계산 정의, 반증 기준, 방어 지표, 세분화와 개인정보 위험을 함께 제시한다.
- 최신 성능 지표의 이름·임계값·지원 상태는 공식 문서를 재확인하도록 표시한다.
- 사용자 수치나 목표치를 근거 없이 만들어내지 않는다.
- 입력에 근거가 없으면 사실을 보충하지 말고 가정, 확인 질문 또는 검증 과제로 표시한다.
- 정적 이미지·텍스트만 제공된 경우 키보드, 포커스, 보조기술, 성능, 동적 상태를 통과했다고 단정하지 않는다.
- 권고를 제시할 때 사용자 영향, 트레이드오프, 검증 방법을 함께 적는다.

## 범위와 근거 수준

이 문서는 공개 표준, 공공 서비스 가이드, 제품 디자인 시스템, UX 연구 자료를 교차해 재구성한 독립적인 한국어 실무 가이드다. 특정 출처의 원문을 대체하거나 특정 조직의 승인·제휴를 의미하지 않는다.

규범 표준에 직접 근거한 요구사항과 여러 출처를 종합한 실무 권고를 구분해 사용한다. 법률·규제 준수, 현재 제품 기능, 최신 브라우저·보조기술 지원, 성능 지표와 임계값처럼 변할 수 있는 사항은 적용 시점의 공식 자료와 실제 구현으로 다시 확인한다.

> **최신성 주의:** 이 가이드는 시간에 따라 정의·도구·권고가 바뀔 수 있는 내용을 포함한다. 현재 공식 문서와 운영 데이터를 확인하지 않은 수치·기능·임계값은 미검증으로 표시한다.
