# 인간-AI 경험 설계

## 한 문장 원칙

AI의 확률적 능력과 한계를 숨기지 말고 사용자가 기대를 조절하고 결과를 검토·수정·거부·복구할 수 있게 설계한다.

## 적용 상황

생성, 추천, 분류, 요약, 자동화, 예측 기능을 사용자 흐름에 넣거나 AI가 사용자를 대신해 행동하는 기능을 설계할 때 사용한다.

## 이 가이드가 답하는 결정

1. 이 문제에서 반드시 지켜야 할 사용자 결과와 품질 경계는 무엇인가?
2. 어떤 상태·맥락·사용자 조건을 포함해야 설계가 실제 환경에서 무너지지 않는가?
3. 어떤 증거와 검증 방법으로 이 결정을 승인·수정·폐기할 것인가?

## 핵심 원리

### 적합한 문제 선택

AI를 넣는 것이 아니라 불확실성과 오류를 감수해도 가치가 있는 사용자 문제인지 먼저 판단한다.

### 능력과 한계의 기대 설정

시작 전에 무엇을 잘하고 못하는지, 어떤 입력이 필요한지, 결과를 어떻게 검토해야 하는지 알려준다.

### 가시적 불확실성

정답처럼 단정하지 말고 근거, 출처, 신뢰 수준, 누락 가능성 또는 검토 필요성을 과업에 맞게 표현한다.

### 사용자 통제

제안 수락·수정·재생성·되돌리기·수동 경로·개인화 해제와 데이터 관리 수단을 제공한다.

### 학습과 피드백의 경계

피드백이 무엇을 바꾸는지, 개인 데이터가 학습·개인화에 어떻게 쓰이는지 투명하게 설명한다.

## 규범적 요구사항

> **MUST**는 위반 시 사용자 과업·안전·접근성·신뢰 또는 검증 가능성이 실질적으로 훼손되는 요구사항이다.  
> **SHOULD**는 특별한 맥락과 근거가 있을 때만 예외를 허용하는 강한 권고다.  
> **MAY**는 선택 가능한 구현 방식이며, 대안의 사용자 결과와 위험을 기록해야 한다.

### MUST

- **MUST:** AI가 수행하는 역할, 사용하지 않는 경우, 사용자 책임, 결과 검토 필요성을 명확히 한다.
- **MUST:** 고위험 결정은 AI 결과만으로 자동 확정하지 않고 적절한 인간 검토와 이의 제기 경로를 둔다.
- **MUST:** 오류·거절·지연·안전 차단·데이터 부족 상태마다 설명과 다음 행동을 제공한다.
- **MUST:** 사용자가 원본 입력·생성 결과·수정 이력·자동 행동을 확인하고 필요한 경우 되돌릴 수 있게 한다.
- **MUST:** 민감 정보, 저작권, 편향, 대표성, 보안, 프라이버시 위험을 기능·데이터·운영 수준에서 검토한다.

### SHOULD

- **SHOULD:** 첫 사용에서 실제 능력을 보여주는 작은 성공 과업과 한계 사례를 함께 제공한다.
- **SHOULD:** 설명은 모델 내부 용어보다 사용자의 결정에 필요한 근거와 영향에 집중한다.
- **SHOULD:** 피드백을 단순 좋아요·싫어요가 아니라 오류 유형과 수정 의도로 수집한다.
- **SHOULD:** 수동 대안과 인간 지원 경로가 AI 실패 시에도 유지되도록 한다.

### MAY

- **MAY:** 프로젝트의 플랫폼·도메인·조직 제약이 정당화하면 다른 패턴을 선택할 수 있다. 단, 사용자 결과, 접근성, 위해, 되돌리기 가능성, 검증 계획을 결정 로그에 남긴다.
- **MAY:** 검증 비용을 줄이기 위해 충실도와 방법을 조정할 수 있다. 단, 조정으로 답할 수 없게 된 질문과 미검증 영역을 명시한다.

## 설계·실행 절차

1. 사용자 문제와 AI가 제공할 고유 가치, AI 없이 가능한 대안을 비교한다.
2. 오류 유형, 오류 비용, 불확실성, 데이터 민감도와 자동화 수준을 분류한다.
3. 첫 사용·정상 사용·불확실한 결과·실패·복구·장기 학습의 경험 흐름을 설계한다.
4. 사용자 통제, 검토, 출처·근거, 피드백, 데이터 설정을 각 흐름에 포함한다.
5. 대표·극단·적대적 입력과 다양한 사용자군으로 품질·편향·안전성을 평가한다.
6. 출시 후 오류 유형, 수정률, 과신, 이의 제기, 피해 신호를 모니터링한다.

## 예외·극단 상황

- 의료·채용·신용·법률·안전처럼 오류 비용과 규제 책임이 큰 결정
- AI가 이메일 전송·삭제·구매·권한 변경처럼 외부 행동을 실행하는 에이전트 흐름
- 출처나 최신성이 중요한 검색·요약 기능
- 개인화가 여러 사용자·조직 데이터와 상호작용하는 업무 도구
- 어린이, 비전문가, 언어 장벽이 있는 사용자가 권위 있는 답으로 오인할 가능성

## 실패 패턴과 교정

| 실패 패턴 | 교정 방법 |
|---|---|
| AI 배지를 붙이는 것만으로 투명하다고 본다. | 역할, 입력 데이터, 한계, 검토 책임, 자동 행동 범위를 맥락에 맞게 설명한다. |
| 모든 결과에 같은 신뢰 표현을 쓴다. | 오류 비용과 근거 가용성에 따라 검토 강도와 설명 수준을 조정한다. |
| 재생성만 제공하고 수정 이유를 학습하지 못한다. | 사용자가 오류 유형과 원하는 방향을 표현하고 결과를 직접 편집하게 한다. |
| AI 실패 시 흐름이 막힌다. | 수동 처리, 저장된 작업, 인간 지원, 재시도 조건을 제공한다. |
| 정확도 평균만으로 출시한다. | 세그먼트별 오류, 심각도, 과신, 실제 과업 성공과 피해를 평가한다. |

## 검증 방법

1. 사용자가 기능의 능력·한계·검토 책임을 자신의 말로 설명하는지 확인한다.
2. 대표 과업에서 제안 수락률뿐 아니라 수정률, 오류 발견률, 과신과 최종 결과 품질을 측정한다.
3. 위험한·모호한·민감한·장문·다국어 입력에서 실패와 복구 흐름을 테스트한다.
4. 자동 행동은 미리보기, 권한, 확인, 실행 로그, 되돌리기와 책임 경계를 검증한다.

## 인수 기준

- [ ] AI가 수행하는 역할, 사용하지 않는 경우, 사용자 책임, 결과 검토 필요성을 명확히 한다.
- [ ] 고위험 결정은 AI 결과만으로 자동 확정하지 않고 적절한 인간 검토와 이의 제기 경로를 둔다.
- [ ] 오류·거절·지연·안전 차단·데이터 부족 상태마다 설명과 다음 행동을 제공한다.
- [ ] 사용자가 원본 입력·생성 결과·수정 이력·자동 행동을 확인하고 필요한 경우 되돌릴 수 있게 한다.
- [ ] 민감 정보, 저작권, 편향, 대표성, 보안, 프라이버시 위험을 기능·데이터·운영 수준에서 검토한다.
- [ ] 사용자가 기능의 능력·한계·검토 책임을 자신의 말로 설명하는지 확인한다.
- [ ] 대표 과업에서 제안 수락률뿐 아니라 수정률, 오류 발견률, 과신과 최종 결과 품질을 측정한다.
- [ ] 위험한·모호한·민감한·장문·다국어 입력에서 실패와 복구 흐름을 테스트한다.

## 에이전트 적용 규칙

- AI 기능 설계 요청에서는 정확성을 보장한다고 표현하지 말고 오류 비용과 검토 모델을 먼저 정한다.
- 모델·데이터·제품 동작이 시점에 따라 변할 수 있으므로 현재 기능은 공식 문서로 별도 검증한다.
- 출력 예시에는 정상 결과뿐 아니라 불확실·거절·복구 상태를 포함한다.
- 입력에 근거가 없으면 사실을 보충하지 말고 가정, 확인 질문 또는 검증 과제로 표시한다.
- 정적 이미지·텍스트만 제공된 경우 키보드, 포커스, 보조기술, 성능, 동적 상태를 통과했다고 단정하지 않는다.
- 권고를 제시할 때 사용자 영향, 트레이드오프, 검증 방법을 함께 적는다.

## 범위와 근거 수준

이 문서는 공개 표준, 공공 서비스 가이드, 제품 디자인 시스템, UX 연구 자료를 교차해 재구성한 독립적인 한국어 실무 가이드다. 특정 출처의 원문을 대체하거나 특정 조직의 승인·제휴를 의미하지 않는다.

규범 표준에 직접 근거한 요구사항과 여러 출처를 종합한 실무 권고를 구분해 사용한다. 법률·규제 준수, 현재 제품 기능, 최신 브라우저·보조기술 지원, 성능 지표와 임계값처럼 변할 수 있는 사항은 적용 시점의 공식 자료와 실제 구현으로 다시 확인한다.

> **최신성 주의:** 이 가이드는 시간에 따라 정의·도구·권고가 바뀔 수 있는 내용을 포함한다. 현재 공식 문서와 운영 데이터를 확인하지 않은 수치·기능·임계값은 미검증으로 표시한다.
