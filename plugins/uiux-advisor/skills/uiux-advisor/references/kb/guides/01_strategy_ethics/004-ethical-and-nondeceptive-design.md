# 윤리적·비기만적 인터페이스

## 한 문장 원칙

사용자의 선택을 돕되 숨김, 강요, 오인, 불균형한 마찰로 사용자의 의도와 이익을 훼손하지 않는다.

## 적용 상황

가입·결제·구독·개인정보·알림·해지처럼 사업 목표와 사용자 자율성이 충돌하기 쉬운 흐름, 실험으로 전환을 최적화하는 흐름, 아동·취약 사용자가 포함된 서비스에 사용한다.

## 이 가이드가 답하는 결정

1. 이 문제에서 반드시 지켜야 할 사용자 결과와 품질 경계는 무엇인가?
2. 어떤 상태·맥락·사용자 조건을 포함해야 설계가 실제 환경에서 무너지지 않는가?
3. 어떤 증거와 검증 방법으로 이 결정을 승인·수정·폐기할 것인가?

## 핵심 원리

### 정보 대칭

가격, 반복 청구, 데이터 사용, 위험, 제한 같은 중대한 정보를 행동 전에 이해 가능한 형태로 보여준다.

### 선택 대칭

동의와 거부, 가입과 해지, 허용과 철회가 의미·가시성·노력 면에서 부당하게 비대칭이 되지 않게 한다.

### 의도 보존

시각적 위계·기본값·문구가 사용자가 하지 않으려던 행동을 실수로 선택하게 만들지 않아야 한다.

### 가역성과 회복

영향이 큰 결정은 검토·수정·취소·철회 경로를 제공하고 결과를 분명히 한다.

### 실험 윤리

A/B 테스트의 성공은 클릭 증가만이 아니라 이해, 후회, 취소, 불만, 개인정보·재정 위해를 함께 평가해야 한다.

## 규범적 요구사항

> **MUST**는 위반 시 사용자 과업·안전·접근성·신뢰 또는 검증 가능성이 실질적으로 훼손되는 요구사항이다.  
> **SHOULD**는 특별한 맥락과 근거가 있을 때만 예외를 허용하는 강한 권고다.  
> **MAY**는 선택 가능한 구현 방식이며, 대안의 사용자 결과와 위험을 기록해야 한다.

### MUST

- **MUST:** 중대한 비용·조건·데이터 사용·자동 갱신·취소 제한을 최종 행동 전에 가리지 않고 제시한다.
- **MUST:** 거부·취소·철회 경로를 의도적으로 숨기거나 불필요한 단계로 지연시키지 않는다.
- **MUST:** 버튼 문구가 실제 결과를 정확히 설명하고 모호한 긍정 표현으로 동의를 위장하지 않는다.
- **MUST:** 사전 선택된 동의, 죄책감 유발 문구, 허위 긴급성, 위장 광고, 반복 방해를 금지한다.
- **MUST:** 실험 계획에 사용자 위해 지표와 중단 기준을 포함하고 취약 사용자군을 별도 검토한다.

### SHOULD

- **SHOULD:** 선택 항목마다 목적, 필수 여부, 결과, 변경 방법을 짧고 평이하게 설명한다.
- **SHOULD:** 동의 기록과 정책 변경 이력을 사용자가 확인할 수 있게 한다.
- **SHOULD:** 고위험 흐름은 법무·개인정보·접근성·사용자 연구 관점의 독립 리뷰를 거친다.
- **SHOULD:** 사용자에게 유리하지 않은 기본값은 그 필요성과 대안을 문서화한다.

### MAY

- **MAY:** 프로젝트의 플랫폼·도메인·조직 제약이 정당화하면 다른 패턴을 선택할 수 있다. 단, 사용자 결과, 접근성, 위해, 되돌리기 가능성, 검증 계획을 결정 로그에 남긴다.
- **MAY:** 검증 비용을 줄이기 위해 충실도와 방법을 조정할 수 있다. 단, 조정으로 답할 수 없게 된 질문과 미검증 영역을 명시한다.

## 설계·실행 절차

1. 흐름에서 사용자의 돈, 데이터, 시간, 평판, 자율성에 영향을 주는 결정을 표시한다.
2. 각 결정에 필요한 정보가 언제 어디서 제시되는지 정보 타임라인을 만든다.
3. 선택지의 문구, 위계, 기본값, 단계 수, 되돌리기 가능성을 대칭성 관점에서 비교한다.
4. 오인·압박·피로·우발 클릭 가능성을 취약 사용자와 보조기술 환경에서 점검한다.
5. 실험 지표에 이해·후회·취소·불만·위해 신호를 포함한다.
6. 출시 후 민원, 환불, 동의 철회, 지원 문의를 모니터링하고 패턴을 교정한다.

## 예외·극단 상황

- 보안·사기 방지 때문에 일부 정보를 사전에 공개하기 어려운 경우
- 법적 필수 동의와 선택 동의가 한 화면에 함께 있는 경우
- 무료 체험에서 유료 전환과 자동 갱신이 연결되는 경우
- 미성년자·인지적 제약·경제적 취약성이 있는 사용자
- 개인화와 추천이 사용자의 데이터나 행동을 장기간 학습하는 경우

## 실패 패턴과 교정

| 실패 패턴 | 교정 방법 |
|---|---|
| 거부 버튼을 낮은 대비의 링크로 숨긴다. | 동일 맥락에서 식별 가능하고 과도한 추가 마찰이 없는 거부 경로를 제공한다. |
| ‘계속’ 버튼이 구매·동의까지 포함한다. | 버튼에 실제 결과와 비용을 명시한다. |
| 취소 이유 설문을 필수로 만든다. | 선택적 피드백으로 두고 즉시 취소 경로를 유지한다. |
| 전환이 높아진 실험을 무조건 성공으로 본다. | 취소·환불·민원·후회·이해도와 장기 유지 품질을 함께 판단한다. |
| 개인정보 선택을 한 번만 제공한다. | 설정에서 쉽게 확인·변경·철회할 수 있게 하고 결과를 설명한다. |

## 검증 방법

1. 사용자에게 선택 결과와 비용을 자신의 말로 설명하게 해 이해 여부를 확인한다.
2. 가입·동의와 해지·철회에 필요한 단계, 시간, 시각적 주목도를 비교한다.
3. 키보드·스크린 리더·확대 환경에서 거부와 취소가 동일하게 발견 가능한지 테스트한다.
4. 실험 전후의 환불, 취소, 불만, 동의 철회와 취약 사용자 영향을 검토한다.

## 인수 기준

- [ ] 중대한 비용·조건·데이터 사용·자동 갱신·취소 제한을 최종 행동 전에 가리지 않고 제시한다.
- [ ] 거부·취소·철회 경로를 의도적으로 숨기거나 불필요한 단계로 지연시키지 않는다.
- [ ] 버튼 문구가 실제 결과를 정확히 설명하고 모호한 긍정 표현으로 동의를 위장하지 않는다.
- [ ] 사전 선택된 동의, 죄책감 유발 문구, 허위 긴급성, 위장 광고, 반복 방해를 금지한다.
- [ ] 실험 계획에 사용자 위해 지표와 중단 기준을 포함하고 취약 사용자군을 별도 검토한다.
- [ ] 사용자에게 선택 결과와 비용을 자신의 말로 설명하게 해 이해 여부를 확인한다.
- [ ] 가입·동의와 해지·철회에 필요한 단계, 시간, 시각적 주목도를 비교한다.
- [ ] 키보드·스크린 리더·확대 환경에서 거부와 취소가 동일하게 발견 가능한지 테스트한다.

## 에이전트 적용 규칙

- 전환 최적화 요청에서 사용자 의도를 왜곡할 소지가 있으면 위험을 지적하고 비기만적 대안을 제시한다.
- 법적 적합성을 단정하지 말고 규제·법무 검토가 필요한 항목을 분리한다.
- 문구와 위계뿐 아니라 단계 수, 기본값, 되돌리기 가능성도 함께 평가한다.
- 입력에 근거가 없으면 사실을 보충하지 말고 가정, 확인 질문 또는 검증 과제로 표시한다.
- 정적 이미지·텍스트만 제공된 경우 키보드, 포커스, 보조기술, 성능, 동적 상태를 통과했다고 단정하지 않는다.
- 권고를 제시할 때 사용자 영향, 트레이드오프, 검증 방법을 함께 적는다.

## 범위와 근거 수준

이 문서는 공개 표준, 공공 서비스 가이드, 제품 디자인 시스템, UX 연구 자료를 교차해 재구성한 독립적인 한국어 실무 가이드다. 특정 출처의 원문을 대체하거나 특정 조직의 승인·제휴를 의미하지 않는다.

규범 표준에 직접 근거한 요구사항과 여러 출처를 종합한 실무 권고를 구분해 사용한다. 법률·규제 준수, 현재 제품 기능, 최신 브라우저·보조기술 지원, 성능 지표와 임계값처럼 변할 수 있는 사항은 적용 시점의 공식 자료와 실제 구현으로 다시 확인한다.
