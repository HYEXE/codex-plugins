# UI/UX Audit Rubric

## 심각도

- **치명적**: 안전·보안·개인정보 침해, 광범위한 과업 불가, 데이터 손실 또는 회복하기 어려운 사용자 피해를 유발할 수 있다.
- **높음**: 핵심 과업을 막거나 주요 사용자 집단을 배제하며, 우회가 어렵거나 오류 가능성이 높다.
- **중간**: 과업은 가능하지만 반복적인 혼란, 지연, 실수나 복구 비용을 만든다.
- **낮음**: 핵심 과업은 유지되지만 이해도, 일관성, 효율이나 완성도를 저하시킨다.

심각도는 영향 크기, 발생 범위, 빈도, 회복 가능성과 위해 가능성을 함께 고려한다. 확인되지 않은 빈도나 사용자 수를 만들지 않는다.

## 근거 확실도

- **높음**: 제공된 화면, 실행 결과, 코드나 명시된 요구사항에서 직접 확인했다.
- **중간**: 확인된 증거와 알려진 흐름을 결합하면 합리적으로 추론할 수 있다.
- **낮음**: 중요한 상태나 환경을 확인하지 못해 검증 가설로만 제시할 수 있다.

확실도가 낮아도 잠재 영향이 크면 우선 검증할 수 있다. 심각도를 낮추는 대신 미검증 상태와 검증 방법을 명확히 한다.

## 증거 레이블

- **관찰**: 화면, 동작, 코드 또는 사용자 제공 사실에서 직접 확인했다.
- **추론**: 관찰된 증거에서 예상되는 결과다.
- **미검증**: 현재 입력이나 환경으로 확인하지 못했다.
- **요구사항**: 제품·표준·정책에서 명시된 조건이다.

## 감사 범위 체크

요청과 관련된 영역만 사용한다.

- 사용자 목표와 성공 상태
- 정보 구조와 탐색
- 콘텐츠, label, instruction과 error message
- 정상·로딩·빈 상태·성공·오류·취소·복구
- 입력, validation, destructive action과 undo
- 키보드, 포커스, 이름·역할·상태와 보조기술
- 색상 외 단서, 확대, reflow, 터치와 motion reduction
- 권한, 동의, 개인정보와 기만 가능성
- 반응형·localization·현실적 극단값
- 실제 성능과 perceived performance
- 측정, acceptance criteria와 회귀 검증

## 수정안 품질

좋은 수정안은 다음을 포함한다.

- 어떤 사용자 결과를 바꾸는지
- 어떤 상태와 사용자가 영향을 받는지
- 기존 흐름과의 tradeoff
- 구현 또는 콘텐츠 변경의 핵심
- 성공을 확인할 수 있는 검증 방법

패턴 이름만 제시하거나 디자인 시스템 컴포넌트로 교체하라는 말만으로 끝내지 않는다.
